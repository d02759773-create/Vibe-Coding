## 二、核心系统用例详述

### UC-01 创建并提交销售订单

| 项目 | 内容 |
|---|---|
| 参与者 | 业务员、内勤 |
| 前置条件 | 用户已登录且有销售订单创建权限；客户、商品档案为启用状态 |
| 主成功场景 | 1. 用户进入销售订单新增页<br>2. 选择客户、发货仓库<br>3. 添加商品明细；系统按 SAR-011 带出单价，用户可手工改价<br>4. 系统展示客户欠款与各行可用库存（只读提醒）<br>5. 用户保存为草稿<br>6. 用户点击「提交审核」<br>7. 系统校验必填项完整<br>8. 订单状态变为待审核 |
| 扩展场景 | E1：可用库存不足——展示预警，仍允许保存草稿<br>E2：客户欠款超阈值——展示提醒，不阻断提交（SBR-010）<br>E3：用户仅保存不提交——停留在草稿 |
| 后置条件 | 提交成功：状态=待审核，关键字段待锁定；草稿：状态=草稿，可继续编辑 |
| 失败处理 | 必填缺失：字段下红色提示 + Toast「提交失败」；客户/商品已停用：阻断选择 |

---

### UC-02 审核销售订单并占用库存

| 项目 | 内容 |
|---|---|
| 参与者 | 内勤（审核人） |
| 前置条件 | 订单状态=待审核；当前用户有审核权限 |
| 主成功场景 | 1. 审核人从待审核列表打开订单<br>2. 核对客户、明细、价格、库存提醒<br>3. 点击「审核通过」<br>4. 系统锁定客户、明细数量、单价等关键字段<br>5. 系统按明细调用库存服务占用可用库存<br>6. 订单状态变为待出库 |
| 扩展场景 | E1：审核人点击「驳回」→ 状态回草稿，可编辑<br>E2：可用库存不足——系统预警（SAR-012 待确认口径下允许继续或占用失败） |
| 后置条件 | 审核通过：状态=待出库，占用成功；驳回：状态=草稿，无占用 |
| 失败处理 | 占用失败：状态保持待审核，Toast「库存占用失败」；无权限：隐藏审核按钮 |

### UC-05 确认销售出库并形成应收

| 项目 | 内容 |
|---|---|
| 参与者 | 仓管 |
| 前置条件 | 销售订单=待出库或部分出库；已存在草稿出库单；用户有出库确认权限 |
| 主成功场景 | 1. 仓管打开待出库出库单<br>2. 拣货后填写各行实发数量（可小于计划出库量）<br>3. 点击「确认出库」并在弹窗确认<br>4. 系统在同一事务内：扣减现存、释放对应占用、生成应收记录、回写订单累计出库量<br>5. 若累计出库+缺量完结未达订单量→订单变为部分出库；若已达→订单变为已完成<br>6. 出库单状态变为已出库 |
| 扩展场景 | E1：实发<计划——按实发确认，差额不自动补发<br>E2：同一订单再次下推新出库单——继续分批出库<br>E3：Mock 案例：40件+55件两次出库，应收累计¥4,750 |
| 后置条件 | 出库单=已出库；库存与应收已更新；订单履约进度已回写 |
| 失败处理 | 实发>可出库余量：阻断；实发=0：阻断；库存扣减失败：整单回滚，Toast「出库确认失败」 |

---

### UC-10 销售退货入库并回冲库存

| 项目 | 内容 |
|---|---|
| 参与者 | 仓管；退货单由内勤/业务员创建 |
| 前置条件 | 已确认销售出库单存在可退数量；销售退货单已创建并关联 outboundId；退货入库单=草稿 |
| 主成功场景 | 1. 内勤基于已出库单创建销售退货单，填写退货原因与数量<br>2. 系统校验退货量≤可退数量<br>3. 仓管创建退货入库单，清点实收数量<br>4. 点击「确认入库」<br>5. 系统事务：回冲库存现存、按退货量冲减应收、更新出库单可退数量、退货单→已完成 |
| 扩展场景 | E1：实收<申请退货量——按实收入库，差额可再退或关闭<br>E2：坏货场景——先登记发货异常再走本用例 |
| 后置条件 | 退货入库单=已入库；库存增加；应收减少；原出库单可退数量减少 |
| 失败处理 | 无 outboundId：拒绝创建退货单；超可退：阻断；已出库订单直接取消：阻断，提示走退货 |
