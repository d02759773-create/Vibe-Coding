# 需求规格说明书（SRS）

需求规格说明书是需求设计阶段的**核心交付物**，将调研结论转化为结构清晰、边界明确的需求基线，是后续业务设计、应用设计和技术设计的正式输入。

---

## 它和 PRD 的本质区别

> [!IMPORTANT]
> 这是最容易混淆的地方，必须说清楚。

| 维度 | 需求规格说明书（SRS） | PRD（产品需求文档） |
| --- | --- | --- |
| **本质** | 需求层的基线文档，回答"做什么" | 设计层的综合交付文档，回答"怎么做" |
| **粒度** | **粗**：功能点级别，不含字段 | **细**：字段、状态机、异常处理、交互细节 |
| **读者** | 业务方、产品、管理层 | 研发工程师、测试工程师 |
| **包含字段/状态机？** | ❌ 不含 | ✅ 含 |

---

## SRS 文档模板

### 1. 引言 / 项目概述

| 项目 | 内容 |
| --- | --- |
| 版本号 | v1.0 |
| 作者 |  |
| 最后更新 | YYYY-MM-DD |
| 评审状态 | 待评审 |

- **项目背景**：为什么要做这个项目
- **项目目的与范围**：覆盖哪些业务场景、哪些主体、哪些系统
- **文档用途**：本文档的使用对象和用途说明
- **关键术语与缩写**：参见《需求调研报告》的「用语与缩写说明」

---

### 2. 背景与现状

- **客户现状与痛点**：参见《需求调研报告》的「调研成果」部分
- **信息化建设的价值定位**：本次信息化能带来什么业务价值
- **干系人信息**：谁关注这个项目，各方的立场和诉求
- **不在范围内（Out of Scope）**：明确排除的内容，防止范围蔓延

---

### 3. 需求综述

> 对调研收集到的需求进行综合描述，既包括业务层面的宏观需求，也包括系统层面的具体需求，为后续设计提供参考。

- **宏观业务场景**：用泳道图呈现主要业务路径（宏观级，不画异常分支）。详细流程推演在业务设计的流程模型中展开。
- **核心需求描述**：每个场景一段话，说明主线是什么

---

### 4. 功能需求

> 详细列出系统必须实现的功能点，是设计、开发、测试的直接依据。
> 
> 具体清单见独立文档：《业务/功能需求一览表》

**关键功能说明**（每个功能点1-2句话描述核心逻辑，细节在应用设计层展开）

| 功能编号 | 功能名称 | 所属模块 | 核心说明 |
| --- | --- | --- | --- |
| F001 |  |  |  |

---

### 5. 非功能性需求

> 与功能需求共同构成系统质量属性，高层描述即可，不含技术方案。

- **性能**：如核心页面加载时间、并发用户数等
- **安全**：如操作日志可追溯、权限控制要求等
- **可靠性**：如系统可用性要求
- **可维护性**：如数据可导出、支持配置化等

---

### 6. 外部依赖与约束

> 本章只记录需求层必须知道的外部依赖和业务约束，不写技术实现方案。

- **外部系统依赖**：需要对接哪些外部系统（如 WMS、POS、财务系统等），依赖它们提供什么业务能力
- **数据源依赖**：依赖哪些第三方或上游主数据、单据、回传结果
- **环境/合规约束**：如必须支持门店网络不稳定、跨集团数据隔离、审计留痕等业务约束

**不要写入**：REST 路径、接口字段协议、数据库表结构、索引、错误码、部署拓扑、具体中间件选型。这些属于技术设计。

---

### 7. 质量保证与验收标准

- **验收流程**：谁来验收，验收流程是什么
- **风险与应对**：已识别的风险点及应对措施
- **里程碑**：关键节点（设计完成/开发完成/上线）

---

### 8. 附件（可选）

- 图形化现状/流程图
- 用例模型、数据模型
- 术语表、参考文献

---

## 与其他文档的关系

| 方向 | 说明 |
| --- | --- |
| **输入来源** | 需求调研报告（提供现状和原始需求） |
| **配套文档** | 业务/功能需求一览表（功能需求章节的独立清单形式） |
| **输出到** | 业务设计、应用设计（作为边界和范围约束） |
| **最终被整合进** | PRD（是PRD的需求层起点，但PRD远比它详细） |

---

## 需求基线变更规则

SRS 一旦评审通过，即作为需求基线。后续业务设计、应用设计或 PRD 编写中发现问题时，按以下方式处理：

| 变化 | 处理方式 |
| --- | --- |
| 新增/删除功能范围 | 更新 SRS 范围章节和业务/功能需求一览表 |
| 优先级变化 | 更新业务/功能需求一览表，并记录原因 |
| 外部系统依赖变化 | 更新外部依赖与约束章节，并同步业务设计和应用设计 |
| 业务规则细化但不改变范围 | 可在业务设计或 PRD 中展开，SRS 保持摘要引用 |
| 字段、状态机、页面交互变化 | 不直接写入 SRS，回到字段清单、应用设计或 PRD 维护 |
