# 业务/功能需求一览表

业务/功能需求一览表是需求规格说明书「功能需求」章节的**独立清单形式**，通过结构化表格管理所有功能需求，实现从需求到设计、开发、测试全周期的可追溯性。

> [!NOTE]
> 本清单与《需求规格说明书》是配套关系：SRS 里的功能需求章节是文字描述，本清单是对应的结构化表格，两者共同构成概要设计阶段的正式输入。

---

## 各列说明

| 列名 | 说明 | 示例值 |
| --- | --- | --- |
| **功能编号** | 唯一编号，从概要设计沿用到开发、测试，保证可追溯性 | F001、F002 |
| **功能/业务描述** | 用客户语言简要说明该功能的用途与边界（1-2句话） | "支持按采购订单创建采购入库单" |
| **业务分类** | 所属业务域或流程，便于按条线梳理 | 采购管理、库存管理、价格管理 |
| **需求优先级** | 根据业务价值、影响范围、法规约束定级 | 高（P0）/ 中（P1）/ 低（P2） |
| **设计难度** | 实现复杂度评估，帮助估算工作量 | 高 / 中 / 低 |
| **所需资源/工期** | 预估开发、测试等资源及时间 | "开发3天、测试1天" |
| **设计顺序** | 功能间的先后依赖关系，影响设计和开发排序 | 数字越小越优先 |
| **状态** | 当前进展 | 待确认 / 已冻结 / 开发中 / 已上线 |
| **备注** | 特殊说明、风险点、关联用例编号等 |  |

---

## 优先级定义

| 优先级 | 含义 | 判断标准 |
| --- | --- | --- |
| **高（P0）** | 必须做，否则阻断上线 | 核心业务流程不可缺失 |
| **中（P1）** | 重要，影响核心体验 | 缺失会导致明显的使用障碍 |
| **低（P2）** | 可选，锦上添花 | 缺失不影响主流程，可延期 |
