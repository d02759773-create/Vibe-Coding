# 建议的文件结构（参考）

> 本目录是**业务设计层的模板参考**，供 AI 和团队成员学习、参照使用。
> 实际使用时，每一期项目单独建立文件夹，参照本结构建立对应子目录。

---

## 目录结构与职责

```
业务设计/
├── 建议的文件结构（参考）/    ← 本目录，AI 学习用模板
│   ├── 业务架构/              ← 业务主体、角色、组织、场景总览
│   ├── 流程模型/              ← 正常/取消/关闭/红冲/异常的业务流程推演
│   ├── 数据设计/              ← 业务实体关系、术语、业务概念枚举、业务规则索引
│   └── 业务用例/              ← 角色视角用例，描述"谁在什么情况下做了什么"
└── [项目期次]/                ← 实际项目，如「物料二期（重新梳理后）/」
```

---

## 业务设计的定位

业务设计回答"业务应该怎么跑、业务规则是否正确、异常场景是否闭环"。它不负责页面字段、控件、接口和数据库实现。

| 目录 | 核心问题 | 典型查阅场景 |
| --- | --- | --- |
| **业务架构/** | 业务全貌是什么？有哪些主体、角色、系统和场景？ | 新人理解项目、跨模块边界讨论 |
| **流程模型/** | 业务从开始到结束怎么走？取消、关闭、红冲、异常怎么处理？ | 评审状态闭环、发现流程断点 |
| **数据设计/** | 业务上有哪些实体、概念、术语和枚举？ | 对齐研发、测试、PRD 字段清单前置语义 |
| **业务用例/** | 从角色视角看，谁在什么情况下做了什么？ | 澄清角色职责、业务边界和主流程 |

## 与其他设计层的关系

```
需求设计（范围和优先级） → 业务设计（业务正确性） → 应用设计（系统怎么承接） → PRD（字段和验收）
```

| 输入/输出 | 说明 |
| --- | --- |
| 输入自需求设计 | 项目范围、优先级、Out of Scope、核心功能清单 |
| 输出到应用设计 | 业务流程、业务规则、业务实体关系、业务用例 |
| 输出到 PRD | 业务规则、流程推演、异常分支、验收口径 |
| 回写到需求设计 | 如果发现需求范围或优先级不成立，必须反向更新需求基线 |

---

## 不应该放什么

| 内容 | 应该放哪里 |
| --- | --- |
| 字段清单中的控件类型、必填性、页面展示范围 | PRD 文档集/字段清单 |
| 页面布局、交互反馈、Mock 数据 | Demo PRD / 应用设计/界面设计 |
| 系统状态机、推送重试、幂等、补偿机制 | 应用设计/流程设计 或 系统机制 |
| REST 路径、DDL、索引、错误码 | 技术设计 |

---

## 阶段门禁

进入应用设计前，至少确认以下内容：

| 检查项 | 要求 |
| --- | --- |
| 场景覆盖 | 正常流程、取消/撤回、关闭/终止、红冲/修正、异常分支已覆盖 |
| 规则来源 | 关键业务规则有来源、日期或待确认状态 |
| 单据链路 | 上游、当前单据、下游、结果单、财务/库存影响已闭环 |
| 术语与枚举 | 业务概念枚举已统一，字段级枚举后续由字段清单承接 |
| 废止口径 | 被替换的旧单据、旧流程、旧术语已从正文同步清理，不能只在标题标注废止 |
