# 建议的文件结构（参考）

> 本目录是**应用设计层的模板参考**，供 AI 和团队成员学习、参照使用。
> 实际使用时，每一期项目单独建立文件夹（如「物料二期/」），参照本结构建立对应子目录。

---

## 目录结构与职责

```
应用设计/
├── 建议的文件结构（参考）/    ← 本目录，AI 学习用模板
│   ├── 应用架构/              ← 系统模块划分与集成边界
│   ├── 流程设计/              ← 状态机、交互流程、时序图
│   ├── 系统机制/              ← 权限、审批、日志等横切关注点（跨期共享）
│   ├── 界面设计/              ← 交互规范和原型链接（高保真稿在 Figma/Axure）
│   └── 系统用例/              ← 系统视角用例（面向研发和测试）
└── [项目期次]/                ← 实际项目，如「物料二期（重新梳理后）/」
```

---

## 各文件夹快速导航

| 文件夹 | 核心问题 | 典型查阅场景 |
| --- | --- | --- |
| **应用架构/** | 系统由哪些模块组成？模块间如何调用？ | 新功能模块归属讨论、集成接口确认 |
| **流程设计/** | 单据的状态是怎么流转的？用户点了什么、系统做了什么？ | 开发排期、状态机边界确认、测试用例设计 |
| **系统机制/** | 权限/审批/日志这些横切机制是怎么设计的？ | 新功能接入权限体系、审批流配置 |
| **界面设计/** | 这个页面的交互规范是什么？原型在哪？ | 开发实现、UI 评审 |
| **系统用例/** | 用户做这个操作的前置条件是什么？系统会做什么响应？ | 测试用例编写、验收标准确认 |

## 与其他设计层的关系

```
业务设计（流程模型）  →  应用设计（流程设计）  →  PRD（字段级细节）
[业务怎么跑]              [系统怎么实现]            [具体字段/校验/异常]
```

> [!NOTE]
> **应用设计 ≠ PRD**：应用设计在功能/组件级别，PRD 在字段/交互细节级别。研发和测试的直接输入是 PRD，不是应用设计。应用设计是 PRD 的上游输入。

---

## 权威源与边界

| 内容 | 应用设计负责 | 不负责 |
| --- | --- | --- |
| 应用架构 | 模块划分、系统边界、外部系统数据流向 | 技术选型、部署拓扑 |
| 流程设计 | 状态机、系统交互流程、跨系统时序 | 字段清单、页面布局细节 |
| 系统机制 | 权限、审批、日志、幂等、补偿、推送重试等横切机制 | 具体接口协议、错误码 |
| 系统用例 | 用户操作和系统响应的前置、主流程、异常、后置 | 业务现实层面的角色职责 |
| 界面设计 | 原型链接、关键交互说明、通用交互模式 | 字段枚举全集、业务规则最终裁定 |

> [!IMPORTANT]
> 如果应用设计与业务设计冲突，先回到业务规则确认；如果应用设计与字段清单冲突，字段定义以字段清单为准，应用设计只调整状态、流程或机制说明。

## 阶段门禁

进入 PRD 编写前，至少确认以下内容：

| 检查项 | 要求 |
| --- | --- |
| 应用架构 | 模块归属、上下游系统、数据流向、同步/异步边界已明确 |
| 状态模型 | L1/L2/L3 或模块自身状态机已符合全局规则；旧状态维度已清理 |
| 系统机制 | 权限、审批、推送重试、幂等、补偿、日志、消息、库存/金额回写有清晰规则 |
| 系统用例 | 核心操作有前置条件、主成功场景、扩展场景、后置条件 |
| 页面入口 | 关键页面清单和原型链接或待补状态已明确 |

---

## 变更回扫要求

| 变更 | 必须回扫 |
| --- | --- |
| 状态模型变化 | 流程设计、系统用例、字段清单、业务 PRD、Demo PRD、前端操作矩阵 |
| 外部系统交互变化 | 应用架构、系统机制、系统用例、流程推演、PRD 验收标准 |
| 横切机制变化 | 所有关联模块 PRD、Demo PRD、权限矩阵、测试用例 |
| 页面入口变化 | 界面设计、Demo PRD、前端路由/菜单、PRD 功能清单 |
