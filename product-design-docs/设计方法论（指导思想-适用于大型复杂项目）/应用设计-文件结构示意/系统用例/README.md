# 系统用例

本目录存放应用层系统用例，从**系统视角**描述「用户与系统如何交互」。面向研发和测试，是测试用例编写的直接依据。

---

## 与业务用例的区别

| 维度 | 业务用例（业务设计层） | 系统用例（应用设计层）|
|---|---|---|
| 视角 | 业务现实（人做了什么） | 系统交互（用户操作了什么、系统响应了什么）|
| 粒度 | 粗（流程/业务步骤级） | 细（界面操作级）|
| 前置条件 | 业务前提（如"已有库存"） | 系统前提（如"单据处于已审核状态"）|
| 读者 | 业务方、产品经理 | 产品经理、研发、测试 |

## 与流程设计的协作关系

- **流程设计**（状态机）回答：这个状态下能做哪些操作？操作后状态变成什么？
- **系统用例**回答：做这个操作的完整交互过程是什么？前置、主流程、异常、后置各是什么？

两者互补，测试人员通常需要同时参考两份文档来设计测试用例。

---

## 应该放什么

- 系统用例说明文档，每个核心功能/操作一份（或多个相关操作合并一份）
- 每个用例包含：参与者、前置条件、主成功场景、扩展场景（异常/替代路径）、后置条件

## 不应该放什么

| 内容 | 应该放哪里 |
| --- | --- |
| 状态机（哪个状态能做什么） | 流程设计/ |
| 字段校验规则的具体定义 | PRD |
| 业务层面的用例（人做了什么） | 业务设计/业务用例/ |

## 系统用例文档模板

```markdown
# [功能模块]系统用例

## 用例目录

| 用例编号 | 用例名称 | 参与角色 | 前置状态 |
| --- | --- | --- | --- |
| SUC-001 | 提交采购订单 | 采购专员 | 单据处于「待提交」状态 |
| SUC-002 | 审核采购订单 | 采购主管 | 单据处于「待审核」状态 |

---

## SUC-001：提交采购订单

| 项目 | 内容 |
| --- | --- |
| **参与者** | 采购专员（主要） |
| **前置条件** | 采购订单已创建，处于「待提交」状态；必填字段已全部填写 |
| **主成功场景** | 1. 采购专员点击「提交」按钮<br/>2. 系统校验必填字段完整性<br/>3. 校验通过，单据状态变更为「待审核」<br/>4. 系统向审核人发送待办通知<br/>5. 页面跳转回列表页，显示操作成功提示 |
| **扩展场景** | A1. 校验失败：系统在对应字段下方显示错误提示，不提交；<br/>A2. 网络异常：提示「操作失败，请重试」，单据状态不变 |
| **后置条件** | 单据处于「待审核」状态；审核人收到待办消息 |
| **业务规则** | - 采购总金额超出授权金额时，需多级审批<br/>- 同一订单不能重复提交 |
```
