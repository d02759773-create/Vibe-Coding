# 系统机制

本目录存放系统级**横切关注点**的设计方案。这些机制被所有功能模块共用，一旦设计好就成为全系统遵守的「基础设施」。

> [!IMPORTANT]
> **跨期共享与目录位置**：系统机制通常在项目启动时设计一次，后续各期次复用。不像流程模型或状态机那样每期单独产出，这里的文档是**跨所有期次共享**的。
> 
> 虽然在模板体系中，系统机制放在应用设计层下，但实际使用时，建议在项目根目录建立 `系统机制/` 顶层目录，与应用设计中的 `系统机制/` 保持同步（或通过链接指向同一个位置）。

---

## 应该放什么

| 机制类型 | 说明 | 典型产出 |
| --- | --- | --- |
| **权限体系** | 角色定义、权限矩阵、数据可见范围规则 | 角色清单、操作权限矩阵 |
| **审批流** | 审批节点、审批规则、流程引擎配置规范 | 审批流说明文档 |
| **配置管理** | 系统可配置项清单、生效范围、默认值 | 配置项清单 |
| **日志与操作记录** | 操作日志标准、审计追踪字段要求 | 日志规范说明 |
| **通知与消息** | 消息触发条件、通知渠道、消息模板规范 | 通知机制设计 |

## 不应该放什么

| 内容 | 应该放哪里 |
| --- | --- |
| 单据的状态机（即使涉及审批状态） | 流程设计/（状态机归属于具体单据） |
| 模块间的调用关系 | 应用架构/ |
| 字段级权限（某个字段谁能编辑） | PRD（字段定义章节） |

---

## 与流程设计中状态机的边界

容易混淆的地方：

- **审批流机制**（系统机制）：定义审批节点有几个、每个节点的规则是什么、如何配置——这是全局规则
- **单据审批状态**（流程设计）：某张具体单据在「待审核」状态下能做什么操作——这是单据自己的状态机

类比：审批流机制是「规则引擎的设计」，单据状态机是「某张单据应用这个引擎的结果」。

## 文档模板（通用权限体系）

```markdown
# 权限体系设计

## 一、角色定义

| 角色名称 | 职责说明 | 覆盖模块 |
| --- | --- | --- |
| 采购专员 | 创建和管理采购订单 | 采购模块 |
| 仓库主管 | 审核入库单、管理库存 | 库存模块 |
| 门店员工 | 提交门店补货需求 | 补货模块 |

## 二、操作权限矩阵

| 功能点 | 采购专员 | 仓库人员 | 门店员工 |
| --- | --- | --- | --- |
| 创建采购订单 | ✅ | ❌ | ❌ |
| 查看采购订单 | ✅ | ✅（仅本仓） | ❌ |
| 提交补货需求 | ❌ | ❌ | ✅ |

## 三、数据可见范围规则

- 普通角色只能查看本人创建或本部门归属的数据
- 主管角色可查看管辖范围内所有下属的数据
- 跨部门数据仅在明确授权的场景下可访问
```

## 多组织权限模板

> 适用于需要区分多个集团或租户的系统。在通用模板的基础上增加"组织归属"维度。

```markdown
## 一、角色定义（多组织）

| 角色名称 | 所属组织 | 职责说明 | 覆盖模块 |
| --- | --- | --- | --- |
| A集团采购专员 | A集团 | 创建和管理采购订单 | A集团物料中心 |
| B集团仓库主管 | B集团 | 审核入库单、管理库存 | B集团物料中心 |

## 二、数据隔离原则

- 各组织用户只能查看归属本组织的数据
- 跨组织数据在各自的模块中各自可见
```
