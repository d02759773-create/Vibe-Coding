# 销售管理业务功能需求一览表

> 文档定位：销售管理模块功能清单与优先级管理工具，与《销售管理需求规格说明书》配套使用。  
> 版本：v1.1 | 状态：待评审（口径冻结见 `context/05-销售管理演示Mock口径.md`）

## 一、功能需求清单

| 编号 | 功能名称 | 功能说明 | 优先级 | 设计顺序 | 需求来源 | 备注 |
|---|---|---|---|---|---|---|
| SF01 | 销售订单创建 | 支持内勤/业务将代理商或批发客户需求录入为销售订单，维护客户、商品、数量、价格等核心业务信息 | P0 | 1 | `context/02` 代理商接单/批发开单高频；`context/01` 两层单据之订单层 | 不含字段级明细；录单前查价/查库存/查欠款依赖 SF04、SF05 及基础资料 |
| SF02 | 销售订单查询与跟进 | 支持按客户、日期、状态等条件查询销售订单，查看执行进度，支撑内勤跟单 | P0 | 2 | `context/02` 订单状态不透明痛点 | 与 SF01 同期设计；状态含待审核/待出库/部分出库/已完结等 |
| SF03 | 销售出库单创建 | 支持基于**已审核**的销售订单生成销售出库单，作为仓库发货的执行依据；支持同一订单多次出库 | P0 | 3 | `context/01` 两层单据；`context/05` Q01/Q02/Q04 | 一期不允许无单直出 |
| SF04 | 仓库出库执行确认 | 仓储人员按出库单完成拣货、打包、发货确认，回写订单履约进度 | P0 | 4 | `context/02` 发货侧；`context/03` 后仓出库确认 | 短少/漏发等异常处理见 SF10 |
| SF05 | 销售库存占用与出库扣减 | 销售订单**审核通过后**占用可用库存，出库确认后扣减现存并释放占用 | P0 | 5 | `context/01` 库存三口径；`context/05` Q01 | 与库存管理模块强依赖 |
| SF06 | 销售应收形成 | 销售出库确认后，自动生成客户应收记录，形成待收款底账 | P0 | 6 | `context/01` 销售出库→应收；`context/02` 应收看不清痛点 | 应收查询能力见 SF07 |
| SF07 | 客户应收与欠款查询 | 支持录单前、发货后按客户查询应收余额与欠款情况，辅助报价与放货决策 | P0 | 7 | `context/02` 录单前问欠款；财务侧应收痛点 | 信用提醒可做，不做强控拦截 |
| SF08 | 销售回款收款登记 | 财务登记客户回款，**人工勾选**一张或多张应收核销；余额可记预收 | P0 | 8 | `context/05` Q07、§六 | 财务独占录入；不做自动认款 |
| SF09 | 销售退货处理 | 基于**原销售出库单**创建退货单并完成退货入库；不允许无单退货 | P1 | 9 | `context/04`；`context/05` Q06、§五 | 已出库不可直接取消订单 |
| SF10 | 发货异常登记 | 登记短少/漏发/坏货：短少走缺量完结，漏发可补出库，坏货走退货 | P1 | 10 | `context/05` Q05、§五 | 一期不做复杂赔付规则 |
| SF11 | 销售出库/订单列表查询 | 提供销售订单、销售出库单的基础列表查询与导出，满足日常查单与对账 | P1 | 11 | `context/02` 内勤查询跟进；`context/03` 基础查询统计 | 复杂经营分析报表不在本期 |
| SF12 | 客户销售往来查询 | 按客户汇总查看销售出库、应收、收款等往来明细，支撑业务与财务基础对账 | P1 | 12 | `context/03` 客户往来查询；`context/02` 财务被动收尾痛点 | 完整总账对账不在本期 |

## 二、功能依赖关系

### 2.1 前置依赖（须先具备）

| 依赖项 | 说明 | 影响功能 |
|---|---|---|
| 基础资料：客户档案 | 销售订单需关联客户 | SF01、SF07、SF12 |
| 基础资料：商品档案 | 销售订单/出库需关联商品 | SF01、SF03 |
| 基础资料：仓库档案 | 出库需指定发货仓库 | SF03、SF04 |
| 库存底账与库存查询 | 占用与扣减依赖统一库存台账 | SF05 |
| 价格体系 | 客户批发价 → 标准批发价 → 手工改价（留痕） | SF01 |

### 2.2 功能间依赖顺序

```
SF01 销售订单创建
  ├──→ SF02 销售订单查询与跟进
  ├──→ SF05 库存占用（录单时）
  └──→ SF03 销售出库单创建
         └──→ SF04 仓库出库执行确认
                ├──→ SF05 库存扣减（出库时）
                ├──→ SF06 销售应收形成
                │      └──→ SF07 客户应收与欠款查询
                │             └──→ SF08 销售回款收款登记
                └──→ SF10 发货异常登记（可选触发）

SF09 销售退货处理 ──依赖──→ SF03/SF04（通常需关联原出库业务）

SF11、SF12 为查询类功能，依赖 SF01–SF08 产生业务数据后才有意义
```

### 2.3 设计顺序建议

1. **第一波（P0 主链路）**：SF01 → SF03 → SF04 → SF05 → SF06 → SF07 → SF08，同步设计 SF02。
2. **第二波（P1 补充）**：SF09 → SF10 → SF11 → SF12。

## 三、暂不进入本期的功能

| 功能 | 不进入本期原因 | 后续触发条件 |
|---|---|---|
| 代理商在线下单 / 自助商城 | 当前通过电话/QQ/微信下单；一期非主营盘 | 代理商规模扩大、自助下单诉求明确且主链路已稳定 |
| 电商平台订单同步 | 明确不属于一期进销存范围 | 电商代发成为主营渠道且需系统对接 |
| 银行/支付流水自动认款 | 私人转账、多单核销场景复杂；一期只做人工登记 | 回款方式标准化、财务对自动认款有明确 ROI |
| 信用额度自动硬拦截 | 需应收链路先稳定；一期信用仅查询提醒 | 应收数据准确、坏账风险管控成为管理层硬性要求 |
| 多级售价审批 / 复杂审批流 | 一期优先跑通主链路，审批仅做基础权限 | 毛利管控、特价审批制度正式落地 |
| 自动补货建议 / 安全库存预警 | 依赖历史数据积累，一期数据不足 | 销售与库存数据稳定运行 3–6 个月以上 |
| 完整财务总账 / 凭证生成 | 进销存止于应收应付与收付款，不做总账 | 企业要求进销存与财务系统一体化 |
| PDA 扫码拣货 / 仓储作业 | 一期仓储以基础确认作业为主 | 仓库作业量、准确率瓶颈倒逼设备化 |
| 复杂销售分析报表（毛利、渠道、趋势） | 先让数据进系统，再谈分析 | 主链路数据质量达标、管理层有分析场景 |
| 零售收银 | 属零售管理模块，与销售管理共用库存但流程独立 | 已冻结：`context/05` Q08；零售模块单独出需求基线 |
