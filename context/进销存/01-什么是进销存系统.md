# 01-什么是进销存系统

## 一、进销存是什么

进销存（Inventory / Purchase-Sales-Stock，常简称 PSS 或「贸易型 ERP 最小集」）是面向**境内贸易、批发分销、门店补货**等企业，用一套系统统一管理 **进、销、存、往来** 四条经营主线的业务后台。

它解决的核心问题：向谁买了什么、卖给了谁、仓库里还有多少、客户/供应商欠多少款。业务发生在**单一国家/本位币**为主、销售渠道以**线下接单、电话/微信、批发开单**为主的场景，不涉及多平台 API、跨境头程与海外履约。

核心业务链路：**采购订货 → 采购入库 → 销售开单 → 销售出库 → 应收应付登记 → 收付款核销 → 库存与往来对账**。

## 二、进销存与跨境电商 ERP、海外仓 WMS 的关系

三套系统可**分别搭建、分别演进**；在腾达科技这类跨境卖家身上，它们在中长期会**分工协作**，但一期练手可以只先做其中一套。

| 系统 | 管什么 | 不做什么（典型边界） |
|---|---|---|
| **进销存** | 境内采购、批发销售、单仓/多逻辑仓库存、客户/供应商往来 | 平台 Listing、多店铺订单 API、头程在途、海外库位作业、多币种利润模型 |
| **跨境电商 ERP** | 在进销存「进-存-往来」之上，扩展**多平台刊登与订单聚合、多仓（国内/海外/FBA）、跨境履约与多币种利润** | 库位级拣货路径、波次拆箱贴标等**现场作业**（交给 WMS 或 ERP 内简化作业页） |
| **海外仓 WMS** | 海外实体仓内的**收货、上架、拣货、打包、发运、盘点、退件**与库位底账 | 采购议价、平台订单、利润核算、供应商账期（归属 ERP） |

- **相对跨境电商 ERP**：进销存是 ERP 的**能力子集与地基**。ERP 的采购/销售/库存/往来模块，在去掉「平台、跨境、多币种利润」后，与经典进销存高度重合；腾达自研跨境 ERP 练手时，国内仓「收货—质检—出库」一段也可先按进销存口径设计，再挂接跨境扩展。
- **相对海外仓 WMS**：进销存（或 ERP）管**业务库存**（哪个逻辑仓、多少可用、被哪张销售单占用）；WMS 管**实物库存**（在哪个库位、哪批货、拣货任务执行到哪一步）。二者通过**入库通知 / 出库指令 + 回传实收实发**对接，库存真相以约定口径为准（常见：ERP 为经营底账，WMS 为仓内执行账，日终或单据确认时对齐）。
- **本项目练手定位（可选路径）**：
  - **只做进销存**：适合先跑通「两层单据 + 库存三口径 + 往来」最小闭环（可参考 `product-design-docs` 中批发销售场景）。
  - **只做跨境 ERP**：国内段能力可内嵌在 ERP，不强制独立进销存产品。
  - **只做海外仓 WMS**：以「ERP 下发 ASN/出库单、WMS 回传结果」为假设边界做原型，主数据与订单仍 mock 或手工录入。

## 三、进销存的典型模块

| 模块 | 核心职责 | 典型单据/功能 |
|---|---|---|
| 基础资料 | 全系统共用的主数据 | 商品档案（SPU/SKU）、客户档案、供应商档案、仓库档案、结算方式/价格政策（视范围） |
| 采购管理 | 管「进」 | 采购订单、采购入库单、采购退货单 |
| 销售管理 | 管「销」 | 销售订单、销售出库单、销售退货单 |
| 仓储与库存 | 管「存」 | 库存查询、调拨单、盘点单、报损单、其他出入库（视范围） |
| 往来与资金 | 管「往来」 | 客户应收、供应商应付、收款单、付款单、对账/欠款查询 |
| 查询统计 | 管「看」 | 进销存汇总表、库存余额、销售/采购排行、客户/供应商账龄 |
| 系统设置 | 运行支撑 | 用户权限、单据编号、期初库存/期初往来、打印模板、操作日志 |

## 四、进销存的核心业务特征

- **单据驱动**：采购订单 → 采购入库 → 库存增加；销售订单 → 销售出库 → 库存减少 + 应收形成；收付款核销往来。
- **两层单据**：**计划层**（采购订单/销售订单）与**执行层**（入库单/出库单）分离；**库存变动只发生在执行层**，避免「只下单就改库存」。
- **库存三口径**（经营侧）：**现存**（账面在库）、**占用**（已被订单锁定未出库）、**可用**（现存 − 占用，还能承诺的量）。境内单仓场景通常不单独拆「在途」；若做「已发货未签收」可扩展为第四口径，一期可不做。
- **数量 + 金额双口径**：管件数，也管采购价/销售价、成本与毛利（本位币为主）；不做复杂的多币种汇损与平台费用分摊。
- **往来挂接执行结果**：出库审核后形成应收，入库审核后形成应付（或按企业习惯挂订单）；录单前可查客户欠款，避免超信用发货。
- **商品快照**：单据明细保存下单时的品名、规格、单位、单价，与日后商品档案变更解耦。
- **上下游联动**：无电商平台 API；客户/供应商、物流信息以**手工维护**为主，外部系统对接为后续扩展项。

## 五、B 端管理后台的典型页面模式

与跨境电商 ERP 共用同一套 B 端交互基线（列表/表单/详情/作业/看板），进销存更侧重**高密度列表 + 开单表单 + 出库作业**，一般不做平台 Tab 与 Listing 映射。

### 页面骨架模式

| 页面类型 | 典型结构 | 说明 |
|---|---|---|
| 列表页 | 查询卡片 + 工具条 + 表格 + 分页 | 采购/销售/库存/往来列表 |
| 表单页 | 页头 + 表头信息 + 明细表格 + 固定底栏 | 采购订单、销售订单、收付款单 |
| 详情页 | 状态区 + 信息卡片 + 明细 + 关联单据 + 底栏动作 | 按状态展示「审核」「下推入库/出库」「作废」等 |
| 作业页 | 待处理明细 + 扫码/数量确认 + 确认提交 | 入库清点、出库拣货（一期可简化为一屏确认） |
| 看板页 | 指标卡 + 简单图表 | 今日开单、待出库、库存预警、欠款 Top（可选） |

### 通用交互规范

- 状态变更仅通过**动作按钮**触发，**不在表单中直接改状态字段**
- 主数据**不提供删除**，统一**停用**；停用后不可被新单引用
- 单据审核后**关键字段锁定**，备注类字段可改
- 必填项标签前加红色星号 `*`
- 底栏按钮：次要左、主要右；成功/失败用 Toast，校验失败用字段下红色文案

### 控件选型指引

| 场景 | 推荐控件 | 说明 |
|---|---|---|
| 选客户/供应商/仓库 | `SelectWithSearch` | 展示 `{Code} {Name}` |
| 选商品 | 商品选择弹窗 | 多选回填 SKU、单位、默认价 |
| 欠款/信用提示 | 只读信息条 + 链接 | 销售开单页展示客户应收余额 |
| 金额 | `NumberInput` | 本位币，2 位小数 |
| 数量 | `NumberInput` | 正整数，出库不超过可用量 |

## 六、进销存的关键设计原则

1. **两层单据 + 往来环节**：计划层订单 → 执行层出入库；应收应付/收付款挂在执行结果或企业约定节点上，与库存变动规则一致。
2. **库存三口径**：所有「能不能卖」的判断以**可用量**为准；销售订单审核/确认时占占用，出库完成时扣现存并释放占用。
3. **最小闭环优先**：一期优先「能采购入库、能销售出库、库存对得平、欠款说得清」，不做多级审批、复杂定价、总账凭证。
4. **与 ERP/WMS 的演进关系**：进销存模块将来可**升级为跨境 ERP 的国内段**；海外履约从 ERP **下发出库指令**到 WMS，避免在进销存里模拟库位级作业。
