# 01-什么是跨境电商 ERP 系统

## 一、跨境电商 ERP 是什么

跨境电商 ERP（Cross-border E-commerce ERP）是面向"通过海外电商平台把商品卖给全球消费者"的卖家，用一套系统统一管理**多平台、多店铺、多币种、多仓库**的经营后台。

它解决的核心问题：我在哪些平台、哪些店铺卖了什么货，订单从哪来、货从哪个仓发、成本多少、回款多少、利润多少、还剩多少库存。相比传统进销存只服务于境内**贸易型企业**，跨境电商 ERP 额外要处理**平台对接（刊登/同步）、跨境物流（头程/尾程）、海外仓与 FBA、多币种结算与利润核算**等复杂度。

核心业务链路：**采购备货 → 刊登上架 → 多平台订单聚合 → 拣货发货（本地/海外仓/FBA）→ 跨境物流履约 → 回款结算 → 利润核算**。

## 二、跨境电商 ERP 与传统进销存、平台的关系

- **相对传统进销存**：进销存聚焦"进-销-存-往来"四条线；跨境电商 ERP 在此基础上，把"销"拆成"多平台刊登 + 多店铺订单聚合"，把"存"扩展为"境内仓 + 海外仓 + FBA 多仓"，把"往来"升级为"多币种成本与利润核算"。
- **相对电商平台（Amazon / eBay / Shopify / TikTok / Temu 等）**：平台是销售渠道，ERP 是卖家自己的经营中枢。ERP 通过 API 与平台对接，把各平台的商品、订单、库存、结算数据聚合到一处统一管理，再把发货结果、库存、物流单号回传给平台。
- **本项目定位**：聚焦**商品刊登、多平台订单、采购备货、多仓库存、跨境履约、成本利润**六条业务主线，不扩展到完整集团 ERP（不含生产制造、人力资源、总账）。

## 三、跨境电商 ERP 的典型模块

| 模块 | 核心职责 | 典型单据/功能 |
|---|---|---|
| 基础资料 | 统一管理所有业务对象，全系统共用 | 商品档案（SPU/SKU）、供应商档案、平台店铺档案、仓库档案、物流渠道档案 |
| 平台与刊登 | 管"上架"——把本地商品同步为平台在线 Listing | 平台授权、Listing 刊登/编辑、库存同步、价格同步、Listing 与本地 SKU 映射 |
| 订单管理 | 管"销"——多平台多店铺订单统一聚合 | 订单同步、订单审核、合并/拆分订单、异常订单处理、退款/退货单 |
| 采购管理 | 管"进"——从备货计划到入库 | 采购需求（补货建议）、采购订单、采购入库单、采购退货单 |
| 仓储与库存 | 管"存"——境内仓/海外仓/FBA 多仓底账 | 库存查询、调拨单（含头程调拨）、盘点单、报损单、海外仓/FBA 库存同步 |
| 发货履约 | 管"发"——拣货打包与物流对接 | 拣货单、发货单、面单打印、物流下单、轨迹跟踪 |
| 财务与利润 | 管"钱"——多币种成本、回款与利润 | 成本核算、平台回款对账、多币种汇率、利润报表、费用（平台佣金/物流/广告）分摊 |
| 查询统计 | 管"看"——经营数据看板 | 销售汇总（分平台/店铺/国家）、库存余额、动销/滞销分析、利润分析 |
| 系统设置 | 系统运行的基础支撑 | 用户权限、单据编号、期初初始化、汇率维护、打印模板、操作日志 |

## 四、跨境电商 ERP 的核心业务特征

- **单据驱动**：所有业务动作都以单据为载体（如采购订单→采购入库单→库存；平台订单→发货单→物流→回款），不是口头沟通
- **多平台多店铺聚合**：同一套后台聚合多个平台、多个店铺的商品与订单，需处理 Listing 与本地 SKU 的映射关系
- **库存是核心底账，且分布多仓**：境内仓、海外仓、FBA 等多个库存节点，库存动作（入库、出库、调拨、头程在途、盘点、报损）最终都影响各仓库存
- **数量 + 金额 + 币种三口径**：不仅管"有多少货""值多少钱"，还要处理销售币种、成本币种与本位币之间的汇率换算
- **成本与利润导向**：跨境成本结构复杂（采购成本 + 头程物流 + 平台佣金 + 尾程派送 + 广告 + 汇损），利润核算是经营决策的核心
- **上下游联动**：采购入库影响库存增加；平台出单→发货→库存减少 + 成本结转；回款到账→利润确认
- **两层单据 + 财务结算**：计划层（采购订单/平台订单）→ 执行层（入库/发货）为两层业务单据；结算（回款、成本、利润）为独立环节，挂接在执行层结果上

## 五、B端管理后台的典型页面模式

AI 生成前端页面时，应遵循以下 B 端后台的常见模式（而非展示站或 C 端风格）：

### 页面骨架模式

| 页面类型 | 典型结构 | 说明 |
|---|---|---|
| 列表页 | 查询卡片 + 工具条 + 表格卡片 + 分页 | 最常用的页面类型，信息密度高、操作路径短（订单/商品/库存列表） |
| 表单页 | 页头 + 表单卡片（头部信息 + 明细表格）+ 固定底部操作栏 | 新增/编辑共享同一套结构，通过路由参数区分 |
| 详情页 | 状态区 + 信息卡片 + 明细卡片 + 关联单据卡片 + 底部操作栏 | 只读展示，操作按钮按状态动态可用 |
| 作业页 | 作业说明 + 待处理明细 + 异常备注 + 底部确认 | 拣货/发货/入库等执行类操作，强调效率和信息可见性 |
| 看板页 | 指标卡 + 图表区 + 明细下钻 | 销售/利润/库存看板，支持分平台、店铺、国家维度筛选 |

### 通用交互规范

- 所有状态变更通过**动作按钮**触发确认弹窗，**不在表单中直接修改状态字段**
- 主数据**不提供删除**，统一用"停用"替代。停用后不可新建引用，历史单据保留完整数据
- 单据审核后**关键字段锁定**，仅备注类字段仍可编辑
- 商品信息在单据中为**快照存储**，与商品档案变化解耦
- 平台/店铺/币种/物流渠道等标识统一展示格式，便于跨平台快速识别
- 必填字段标签前加红色星号 `*`
- 操作成功/失败用 Toast 反馈，阻断类校验用字段下方红色文字提示
- 固定底部操作栏的按钮顺序：次要操作左、主要操作右

### 控件选型指引

| 场景 | 推荐控件 | 说明 |
|---|---|---|
| 选择档案（供应商/仓库/店铺/物流渠道） | `SelectWithSearch` | 支持按编码或名称搜索，展示格式 `{Code} {Name}` |
| 选择商品 | 商品选择弹窗 | 支持搜索+多选，选中后自动回填名称/规格/SKU/单位 |
| 平台/店铺筛选 | `Select` 或 Tab 栏 | 多平台多店铺场景优先用级联选择或 Tab 栏 |
| 币种/汇率 | `Select` + `NumberInput` | 币种选择联动汇率，金额按币种展示符号 |
| 日期选择 | `DatePicker` | 精确到日，可通过 `disabledDate` 限制可选范围 |
| 日期区间筛选 | `DateRange` | 列表页筛选区使用，含快捷选项（今天/本周/本月） |
| 状态筛选 | `Select` 或 Tab 栏 | 状态数量 ≥ 3 时优先用 Tab 栏，体验更好 |
| 批量搜索 | `BatchSearchInput` | 支持换行或逗号分隔多值粘贴（订单号/SKU/物流单号） |
| 金额输入 | `NumberInput` | 按币种前缀（如 `¥`/`$`），2 位小数，千分位展示 |
| 数量输入 | `NumberInput` | 正整数，不展示步进按钮 |
| 文本备注 | `Textarea` 或 `Input` | 根据预估字数选择，标注字符上限 |

## 六、跨境电商 ERP 系统的关键设计原则

1. **两层单据架构 + 财务结算环节**：计划层（采购订单/平台订单）→ 执行层（入库/发货）为两层业务单据；结算（成本结转、回款、利润）为独立环节。执行层单据必须基于计划层创建，库存变动只发生在执行层。
2. **库存四口径 + 多仓分布**：现存（实际有的）、占用（已被订单锁定未发货）、可用（还能承诺的）、在途（头程/调拨在路上）。且每个口径需按境内仓/海外仓/FBA 分仓统计。
3. **Listing 与本地 SKU 映射**：平台在线商品（Listing）与本地库存 SKU 是多对多关系，一个本地 SKU 可对应多平台多 Listing，映射关系是订单下推、库存同步的基础。
4. **多币种与成本利润分离**：销售币种、采购成本币种、本位币三者用汇率换算；成本按"采购 + 头程 + 平台佣金 + 尾程 + 广告 + 汇损"分层归集，利润核算独立成模块。
5. **最小闭环优先**：一期不做复杂规则（智能补货、动态定价、多级审批、精细分摊），先把"商品刊登得出、订单聚合得进、货发得出、库存对得平、利润算得清"这条主链路做好。
