# 11-平台刊登与铺货（一期模拟）

> 文档定位：一期 **P0/P1 主链**上的「平台与刊登」能力口径。**不对接 Amazon SP-API**，在 ERP 内维护 **模拟平台 Listing** 并完成 **单店刊登 / 改标题 / 改价 / 多店铺批量铺货**；发布结果用于演示、PRD 与前端原型，并为 **Amazon 映射**、订单模拟、库存策略联调提供数据底座。  
> 关联：`06` §4.2a、`09` 阶段 1～2、`03` §4.1、`04` S1。

---

## 一、业务背景

运营在本地 **SPU/SKU** 与 **BOM** 就绪后，需要把可售规格「挂到」各 Amazon 美国站店铺（约 10 个）的 **在线 Listing** 上：维护标题、售价等展示字段，并产生 **MSKU / ASIN / FNSKU** 与本地 SKU 的对应关系，供贴标、货件、订单行映射使用。

一期 **不调用平台 API**；系统在用户点击 **模拟发布 / 模拟铺货** 后，在 ERP 内生成或更新 **平台 Listing 档案**，并 **联动写入或更新「Amazon 映射」**（规则见 §四）。与真实 Seller Central 的差异在界面与帮助文案中标注「模拟」。

---

## 二、功能范围

### In Scope（一期）

| 能力 | 说明 |
|---|---|
| **平台 Listing 档案** | 按 **店铺 + MSKU**（或系统生成的模拟 MSKU）唯一；挂接本地 **SKU**；含标题、卖点摘要、售价（USD）、刊登状态等 |
| **新建刊登** | 从本地 SKU（或 SPU 下勾选多 SKU）创建 Listing **草稿**；可预填 SPU 名称、主图等可售商品字段 |
| **编辑 Listing** | 改 **标题**、改 **售价**（及 PRD 定义的其它展示字段）；**已模拟上线**的 Listing 改价/改标题走 **保存并模拟同步** 动作（仍无 API） |
| **单店模拟发布** | 草稿 → **模拟发布** → 状态变为 **已上线（模拟）**；生成模拟 **ASIN**（若为空）、记录发布时间 |
| **批量铺货** | 同一本地 SKU（或 SPU 批量选 SKU）**勾选多个店铺**，可套用标题/价格模板（如店铺后缀、统一加价规则）；生成 **铺货任务** 与多行 Listing；**模拟执行** 后批量上线并写映射 |
| **与 Amazon 映射联动** | 模拟发布/铺货成功后，**自动维护** `商品中心 → Amazon 映射`（见 §四） |
| **列表与详情** | 按店铺、SKU、状态筛选；详情只读展示关联本地商品与映射键值 |

### Out Scope（一期）

| 项 | 说明 |
|---|---|
| **SP-API / 真实刊登** | 真实创建/更新 Amazon Catalog、库存/价格推送；归 **阶段 8** 或单模块 PRD 升级 |
| **广告、A+、变体合并规则引擎** | 仅保留 Listing 主字段；复杂变体关系 PRD 可简化 |
| **非 Amazon 平台** | 与 `02` 一致 |
| **库存同步到平台** | 刊登模块不驱动可售库存推送；库存真相仍在 ERP 执行层（`03` §3.2） |

## 三、单据与状态（业务概念名）

### 3.1 平台 Listing（模拟）

| 状态 | 含义 | 典型动作 |
|---|---|---|
| **草稿** | 未对任何店铺「上线」 | 编辑、删除草稿 **[PRD 定是否允许删]**、模拟发布 |
| **已上线（模拟）** | 该店铺下视为已在平台可售 | 改标题/改价（保存并模拟同步）、**停用**（模拟下架） |
| **已停用（模拟）** | 模拟下架，历史保留 | 重新启用（模拟上架） |

> 状态变更仅通过 **动作按钮** 触发，不在表单中直改状态字段（`AGENTS.md`）。

### 3.2 铺货任务（批量）

| 状态 | 含义 |
|---|---|
| **待执行** | 已选店铺与 SKU 行，未模拟执行 |
| **已完成** | 全部目标店铺已生成/更新 Listing 与映射 |
| **部分失败** | 某店铺校验失败（如 SKU 已停用、该店 MSKU 冲突）；成功行仍落库，失败行可重试 |

## 四、与本地 SKU、Amazon 映射的关系

```mermaid
flowchart LR
  SKU[本地 SKU]
  L[平台 Listing 模拟]
  MAP[Amazon 映射]
  SKU --> L
  L --> MAP
```

| 规则 | 说明 |
|---|---|
| **主数据** | 库存、委外、货件只认 **本地 SKU**；Listing 是渠道展示与平台编码载体 |
| **一对多** | 同一本地 SKU 可在多店铺各有独立 Listing（不同 MSKU/标题/价） |
| **映射写入** | **模拟发布/铺货成功** 时：若该 **店铺 + 本地 SKU** 无映射行，则 **新增** MSKU、ASIN、FNSKU（FNSKU 可手工补或按规则生成模拟码）；若已有映射，则 **更新** 与 Listing 一致的 MSKU/ASIN（FNSKU 一般不自动覆盖，PRD 定） |
| **冲突** | 同一店铺下 MSKU 不可重复；铺货前校验 |

**与订单模块**：阶段 5 平台订单可为 **导入/模拟订单**；行上 MSKU 解析依赖上述映射（`08`）。

## 六、模拟行为（前端 / Demo 约定）

| 用户动作 | 系统行为（无 API） |
|---|---|
| 模拟发布 | 生成 `ASIN_SIM_` + 时间戳或序号；MSKU 默认取表单或 `店铺编码-SKU编码`；Toast「模拟发布成功」 |
| 保存并模拟同步 | 更新 Listing 档案字段；映射表同步 MSKU/ASIN 展示字段（如有） |
| 模拟下架 | Listing → 已停用；映射行 **停用** 而非物理删除 |
| 批量铺货执行 | 按店铺循环上述逻辑；任务详情展示每店结果 |

## 七、实施阶段（见 `09`）

| 阶段 | 优先级 | 交付 |
|---|---|---|
| **阶段 1** | P0 | 平台 Listing 列表/表单/详情；单店 **模拟发布**；映射联动 |
| **阶段 2** | P1 | **批量铺货** 任务；改标题/改价 + **保存并模拟同步** |

**验收（阶段 1）**：一款色码 SKU 可在 1 个店铺模拟上线，且 **Amazon 映射** 可查对应 MSKU/ASIN。  
**验收（阶段 2）**：同一 SKU 可一次铺至 ≥2 个店铺，映射行正确、MSKU 不冲突。
