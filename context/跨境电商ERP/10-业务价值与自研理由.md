# 10-业务价值与自研理由

> **文档定位**：为管理层与项目组说明腾达科技 **0→1 自研跨境电商 ERP（一期）** 要解决的经营问题、可预期的收益，以及 **为何自研、自研什么、不做什么**。  
> **能力边界**以 `02` 第八节、`06` 菜单地图为准；**价值释放顺序**见 `09`；**端到端单据**见 `04`。

---

## 一、核心结论（一页读懂）

| 维度 | 结论 |
|---|---|
| **公司事实** | 跨境女装品牌商；**委外成衣 + 国内单仓增值 + Amazon US 约 10 店 FBA 备货**；本位币 CNY，Amazon 回款 USD（按账单日折算）。 |
| **一期系统定位** | 不是「全行业跨境 SaaS」，而是本公司 **FBA 备货主链的唯一作业与底账系统**（`04`），把领星、Excel、微信里的关键事实 **单据化、状态机化、可追溯**。 |
| **核心价值** | 在 **多色码 SKU、强季节补货** 下，做到 **供得上、发得准、账说得清**；并把运营—供应链—仓储—账务—工厂协同收成 **可审计的系统契约**。 |
| **自研本质** | 用 **本公司的单据与状态机** 表达经营语法（两层委外、色码 BOM、质检—压气—贴标、四口径库存、按单总价月结等），而非在通用 ERP 上堆自定义字段。 |
| **与领星关系** | 领星保留 **多平台卖家通用能力** 的参考价值；自研 **收窄为 Amazon US + 委外主链**，在领星难以深度贴合的区段形成 **边际价值**（见 §四）；切换按 `02` §九 **分域单写、分阶段切**。 |
| **边界** | **内建**主链与底账；**外留**平台连接器、物流能力等可分阶段对接；**不做**完整集团 ERP、MES、总账、领星历史自动迁移等（`02` §八）。 |

## 二、经营上要解决什么问题

### 2.1 成败取决于主链，不取决于「有没有跨境软件」

经营模式：**内部定款与 BOM → 成衣委外 → 国内仓增值 → FBA 备货 → Amazon 销售（FBA 配送）**。系统建设应直接服务三条经营底线：

| 底线 | 含义 | 一期系统要支撑的事实 |
|---|---|---|
| **供得上** | 委外产能与到货跟得上动销 | 计划层审批、派单拆厂、在产管道可见；补货建议可复核、不绕过审批（`07`） |
| **发得准** | 国内实装与 Amazon 货件、FNSKU/箱唛一致 | 映射同源、备货占用国内可用、改仓改箱审批留痕、在途与接收对齐 |
| **账说得清** | 国内可用、头程在途、FBA 可售、在产管道同一套口径 | 库存只在执行确认后变动；加工费与回款挂接执行单据，可举证 |

### 2.2 已验证痛点（`02` §七）与目标能力

| 编号 | 现状痛点 | 自研要换来的能力 |
|---|---|---|
| P01 | 委外、指定面辅料、成衣厂人民币结算外挂 | 委外供应链 + 协同 + 委外对账一体化 |
| P02 | 国内仓工位难留痕 | 仓储分菜单作业；库存变动点明确（如上架确认） |
| P03 | 货件与国内实装、改仓改箱衔接弱 | 货件计划 / 备货作业 / 改仓改箱审批 / 在途接收 |
| P04 | BOM、SKU、FNSKU 多套维护 | 生产中心与商品中心、Amazon 映射 **同源** |
| P05 | 国内可用 vs FBA 可售口径不一致 | 库存中心 **四口径** + 流水追溯（`03` §7.1） |
| P06 | 短少/溢装无标准单据 | 收货清点、入库异常、超交退货 |
| P07 | 领星定制受路线图约束 | 关键流程、AI 补货/派单按本公司规则迭代 |
| P08 | 切换期双系统风险 | **分域单写** + 分阶段切领星（`02` §九） |
| P09 | 工厂协同无统一留痕 | ERP 内 **外部供应商角色**（`05`） |

## 三、自研 ERP 带来的业务价值

### 3.1 战略层：主链收成可经营的数字资产

- 把「**款—产—仓—发—卖—算**」从分散工具收成 **一条可执行、可对账的主链**，支撑从领星 **分域切换** 而非长期双写。
- 沉淀 BOM 版本、派单规则、质检比例、补货参数、对账异议闭环等 **自有数据与日志**，为后续 AI 与报表 **越用越准** 提供基础（`07`）。

### 3.2 经营层：收入、成本与现金

| 价值类型 | 业务含义 | 一期如何体现 |
|---|---|---|
| **收入与周转** | 补货更准、断货更少、呆滞更可控 | 统一 SKU/BOM/FNSKU；四口径库存 + 平台订单动销 → AI 补货建议；货件计划 **占用国内可用**，避免「系统有数、现场没货」 |
| **成本与损耗** | 头程、加工费、不良与改仓成本可追因 | 委外 **按单总价** 月对账；质检/溢装/返修有标准单据；备货记录实装箱重与交接，改仓改箱审批留痕 |
| **现金与对账** | 人民币委外/物流与美元回款在同一经营视图 | 本位币 CNY、Amazon 账单 USD 按 **账单日** 折算（`02`）；委外对账、回款对账挂接执行单据 |

### 3.3 组织层：从「口头 + 表格」到「系统契约」

一期把 **运营（需求与审批）→ 供应链（派单与跟单）→ 仓储（收货到上架）→ 运营备货（货件）→ 账务（对账）** 以及 **成衣厂 / 面辅料厂（ERP 内供应商角色）** 接到同一套菜单与权限上（`06`）：

- **责任边界清晰**：采购需求不含厂与加工费总价，派单后才落厂与按单总价；质检不合格不得上架。
- **审批可审计**：采购需求、改仓改箱等通过 **动作按钮** 改状态，符合内控与纠纷举证（项目全局规范）。
- **外部协同可留痕**：工厂确认采购单、收货通知约仓、对账确认/异议，降低 P09 类微信协同风险。

### 3.4 主链路分域价值（与 `04` 阶段对应）

以下按 **业务主链** 归纳价值；菜单明细与 `06` 一一对应，此处不重复罗列每张菜单。

```mermaid
flowchart LR
  A[款与可卖] --> B[委外供产]
  B --> C[国内仓作业]
  C --> D[库存管道]
  D --> E[FBA 备货]
  E --> F[平台卖与算]
```

| 主链区段 | 覆盖菜单域（`06`） | 价值主张 | 主要受益角色 | 若不建设时的典型损失 |
|---|---|---|---|---|
| **款与可卖** | 商品中心、生产中心、平台刊登（`11`） | 色码 SKU、**色码 BOM 版本**、FNSKU 映射、模拟刊登与铺货同源 | 商品、版师、运营 | 贴标/货件驳回、补货算错色码；上新演示与培训成本高 |
| **委外供产** | 委外供应链 | 需求双审 → 派单拆厂 → 成衣采购单（BOM 快照、按单总价）→ 到货跟踪；AI 建议 **人工确认** | 运营、供应链 | P01、P06、P09；加工费与到货状态无法对齐财务与仓库 |
| **国内仓作业** | 仓储作业 | 通知单先审后送；清点与溢装规则；抽检—压气—贴标—上架；异常单据化 | 仓储、质检、供应链 | P02；「国内库存」与可发 FBA 实物不一致 |
| **库存管道** | 库存中心 | 国内现存/占用/可用、头程在途、FBA 逻辑仓、**流水追溯** | 运营、账务 | P05；货件与补货建立在错误管道库存上 |
| **FBA 备货** | Amazon FBA | 计划占用可用；拣货—装箱—箱唛—称重—出库；改仓改箱双审 | 运营、仓储 | P03；头程成本与责任难追溯到实装批次 |
| **平台卖与算** | 订单与售后、财务中心 | FBA 订单进 ERP 支撑动销与异常治理；委外/物流月结与 Amazon 回款本位币视图 | 运营、账务、客服 | 补货缺动销源；对账仍靠 Excel 与微信 |
| **基座** | 基础资料、系统设置、外部供应商菜单 | 档案单一来源；角色分权；协同账号与参数可配置 | 全员、管理员、工厂 | 阶段 0 无法开第一张业务单（`09`） |

**订单与售后说明**：消费者订单由 **FBA 配送**，不驱动国内仓销售出库；一期价值在于 **销售事实可见、映射与回款可对账**（`08`），而非国内拣货。

**外部供应商**：成衣厂（确认单、交期、送货、对账）与面辅料厂（用料、供料）在 ERP 内协同；本公司仍 **不结面辅料账**（`05`）。

## 四、为什么要自研（而非仅依赖领星或外采通用 ERP）

### 4.1 通用产品的「默认模型」与本公司不一致

| 本公司事实 | 通用 SaaS 常见假设 | 不匹配的后果 |
|---|---|---|
| 成衣 **委外**，本公司 **不结面辅料账** | 采购—入库—应付一条线 | 面辅料只能外挂；BOM 与应付对不上 |
| **采购需求 → 运营双审 → 供应链派单** | 运营直接下采购单或 MRP | 权限与数量约束难落地；拆厂逻辑变通成本高 |
| 国内仓 **收货—抽检—压气—贴 FNSKU—上架** | 简单采购入库 | 不良与可发 FBA 库存混在一起；质量批次不可追 |
| **按单总价** 委外加工费、**月对账** | 按 SKU 成本或工序账 | 与工厂结算口径不一致 |
| **色码维度 BOM** + 委外单快照 | 商品层 BOM 弱或整款一套 | 贴标错误、货件驳回、补货算错色码 |
| 一期 **单平台 Amazon、单国内仓** | 功能大而全 | 为用不到的模块付费，关键链仍靠 Excel |

自研换的是 **可执行的经营语法**，不是字段堆砌。

### 4.2 相对领星的边际价值（一期收窄口径）

| 区段 | 领星典型强项 | 本公司一期自研侧重点 |
|---|---|---|
| 平台与经营 | 多平台、广告、利润看板等 | **Amazon US 主链底账**；刊登一期为 **ERP 内模拟**（`11`） |
| 采购与生产 | 卖家通用采购入库 | **两层委外**、指定面辅料协同、按单总价月结 |
| 仓储 | 跨境卖家入库发运 | **女装增值工位**（质检、压气、贴标）与状态机 |
| 备货 | FBA 货件工具 | 与国内实装、占用、改仓改箱 **同一系统闭环** |
| 定制与资产 | 受 SaaS 路线图约束 | 状态机、AI 人机协同、对账与日志 **自有迭代** |

### 4.3 经济性与「何时自研合理」

**不适合**用自研概括的（一期 Out Scope）：完整集团 ERP、MES、总账税务、多平台聚合、领星历史自动迁移等（`02` §八）。

**本公司符合自研合理性的情形**：

1. **主链长、差异化高**：BOM 到 FBA 接收是主要成本池与运营核心，系统应随流程演进。
2. **数据要成资产**：规则与参数沉淀在自有库表，支撑 AI 与经营分析（`07`）。
3. **长期 TCO**：领星持续订阅 + 人工补表 + 货件/断货 **隐性成本**；自研用建设投入换 **边际迭代可控**（须严守范围，避免做成「第二个领星」）。
4. **可控切换**：按 `09` 纵向切片，先委外—入库—备货，再叠订单、财务、AI，降低大爆炸风险。

### 4.4 自研 ≠ 全栈自研

- **内建**：本公司必须说了算的 **主链作业、库存底账、委外与对账真相源**（与 `03` 系统边界一致）。
- **外留 / 分阶段**：Amazon SP-API、物流轨迹等连接器；不重复造「全行业平台中间件」轮子。

## 五、价值如何落地与如何验收

### 5.1 与实施阶段的对应（`09`）

价值 **按纵向切片释放**，不必等全模块上线：

| 阶段 | 释放的核心价值 |
|---|---|
| 0～1 | 主数据与 BOM 可信；映射与模拟刊登可演示 |
| 2 | 委外计划可审、可派、可跟；加工费挂单 |
| 3 | 国内库存底账真实；质检与异常可追 |
| 4 | FBA 备货与在途口径成立 |
| 5～6 | 销售与回款进同一视图；工厂协同与月结对账在线化 |
| 7～8 | 补货/派单人机协同；API 减手工 |

**MVP 里程碑**（阶段 0→4）：即使暂无订单 API 与 AI，也应能演示 **委外 → 上架 → 货件 → 在途 → FBA 接收** 闭环（`09` §五）。

### 5.2 建议关注的经营 KPI（项目层）

| 指标方向 | 说明 |
|---|---|
| 断货率 / 有货率 | 爆款 SKU 在 FBA 可售与补货节奏（长期） |
| 货件拒收 / 改仓改箱次数 | 映射与实装一致性 |
| 入库差异闭环时效 | 短少、溢装、不合格批次单据化处理时间 |
| 委外对账差异率 | 月结异议单占比 |
| 双系统并行期 | 库存与在途 **对照一致** 后关闭领星对应录入（`02` §9.1） |

### 5.3 价值折损风险（需管理层共识）

| 风险 | 说明 |
|---|---|
| **切换期效率** | 分域单写前期可能增加协调成本；用 `02` §九 阶段切换降低风险 |
| **范围膨胀** | 若一期追求「全行业 ERP」，会稀释主链价值；严守 Out Scope |
| **数据质量** | AI 与报表依赖映射、期初、订单同步；阶段 1、5 须扎实 |
