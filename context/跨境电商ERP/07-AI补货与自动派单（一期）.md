# 07-AI 补货与自动派单（一期）

> 文档定位：一期 **AI 辅助决策** 的产品逻辑——**自动补货（建议）** 与 **自动派单（建议）**。  
> **一期原则**：AI 产出可复核的**建议方案**与**草稿单据**，**不替代**已冻结的人工节点（运营组长/总监审需求、供应链专员确认派单、成衣厂确认采购单）。  
> 配套：`02` §3.4 委外流程、`04` S2、`06` 菜单。

---

## 一、一期边界（能做什么 / 不做什么）

| 能力 | 一期 In Scope | 一期不做 |
|---|---|---|
| **AI 自动补货** | 按规则+数据计算缺口，生成 **补货建议**；可 **一键转为采购需求草稿** | 不经人审自动提交采购需求；不经人审自动生成货件/采购单 |
| **AI 自动派单** | 对已审采购需求生成 **派单方案**（拆单、选厂、建议交期/参考加工费）；专员确认后 **生成成衣采购单** | 不经人确认自动下达工厂；自动谈价签合同 |
| **模型形态** | 以 **可解释规则引擎 + 统计动销** 为主；可选用 LLM 生成**自然语言说明**（非黑盒决策） | 无监督端到端「全自动供应链」 |
| **留痕** | 每次建议保存：**输入数据快照、规则版本、建议结果、采纳/修改/驳回人** | — |

## 二、AI 自动补货（建议 → 采购需求）

### 2.1 要解决什么问题

在 **Amazon 美国站、约 10 店铺、色码 SKU 多** 的情况下，避免：

- **FBA 断货**（可售不足、动销快）  
- **国内呆滞**（盲目下单成衣）  
- **管道断裂**（只看 FBA 库存、忽略在途、在产、国内现货）

补货建议的对象是 **「要不要成衣生产、要多少」**，输出接入现有 **采购需求** 流程，而不是绕过流程。

### 2.2 计算单位与粒度

| 项 | 口径 |
|---|---|
| 计算粒度 | **店铺 + 本地 SKU**（同一 SKU 多店铺分别算，再可合并为一条需求行） |
| 时间窗 | 默认近 **7 / 14 / 30 天** FBA 订单动销（日均销量 ADS），权重可配置（如 7 天 0.5 + 30 天 0.5） |
| 目标库存 | **目标覆盖天数** `T`（全局默认 + 按品类/款/SKU 覆盖），表示「希望管道末端（含 FBA 可售）能撑多少天」 |

### 2.3 「管道库存」位置（供给方）

对每个 **店铺 + SKU**，汇总**可用供给**（不计已占用、不含不良品）：

| 符号 | 含义 | 数据来源 |
|---|---|---|
| `F` | FBA 逻辑仓 **可售/可用** | 平台同步 |
| `D` | **国内仓可用**（已上架、未占用） | ERP 库存 |
| `Tt` | **头程在途**（已发未收 FBA） | ERP 在途 |
| `W` | **在产在途**（已下达成衣采购单、未入库数量） |  open 成衣采购单未收量 |
| `R` | **已审未派满**（采购需求剩余未派单量） | 需求 − 已派单累计 |

**管道位置（简化）**：`Position = F + D + Tt + W + R`  
（一期可先不把「已审未派满」算入可售，只作展示；是否计入在 PRD 开关，默认 **计入** 以免重复下单。）

### 2.4 需求与建议量（规则核心）

**前置周期** `L`（天，可分层配置）：

`L = 生产周期 + 国内收货质检上架周期 + 头程周期`  
（默认值在 **系统设置 → 补货参数** 维护；可按品类/SKU 覆盖；暂无历史时用默认。）

**目标管道库存量**（件）：

`TargetQty = ADS × (T + L)`  

**缺口**：

`Gap = TargetQty − Position`  

若 `Gap > 0`，则产生 **补货建议量** `SuggestQty`：

- 先取 `Gap`，再按 **最小下单量 / 成衣厂整单倍数** 向上取整（参数，默认 1）  
- 若 `ADS = 0` 且 `F + D` 低于**安全库存下限**（可选），可给「人工关注」建议而非强制量  

**建议需求交期**：

`NeedDate = 今天 + L`（或按运营日历顺延）

### 2.5 双通道提示（一期可选同屏展示）

| 通道 | 条件 | 建议动作 |
|---|---|---|
| **成衣补货（主）** | `Gap > 0` 且国内现货不足以覆盖缺口 | 生成 **采购需求** 建议行（`SuggestQty`） |
| **FBA 发货补货（辅）** | `D > 0` 且 `F` 偏低但 `Gap` 主要由 FBA 侧引起 | 提示 **可创建 FBA 货件计划**（生成草稿或待办，**不自动占用库存**）；一期可与成衣建议分 tab 展示 |

### 2.6 人机协同流程

| 步骤 | 角色 | 动作 |
|---|---|---|
| 1 | 系统 / 运营 | **定时任务**（如每日）或 **手动触发**「重新计算补货建议」 |
| 2 | 系统 | 写入 **补货建议单**（状态：待处理），行级含：店铺、SKU、ADS、Position 分解、Gap、SuggestQty、NeedDate、**依据说明**（规则项中文） |
| 3 | 运营专员 | 在 **AI 补货建议** 中勾选行 → **生成采购需求草稿**（可合并多店铺同款为一需求行） |
| 4 | 运营专员 | 编辑数量/交期后 **提交** → 走 **组长 → 总监** 审批（`02` §3.4） |

**不自动**：提交审批、派单、下达工厂。

### 2.7 「AI」在一期的含义

| 层次 | 内容 |
|---|---|
| **决策层（必做）** | 上述公式与参数化规则，输出结构化建议与可追溯依据 |
| **增强层（可选）** | LLM 对单行建议生成摘要（如「近 7 天动销上升、FBA 仅剩 12 天覆盖」）；**不得改变数量** |

## 三、AI 自动派单（建议 → 成衣采购单）

### 3.1 要解决什么问题

已审 **采购需求** 往往需 **拆单、选厂**。专员凭经验耗时且难留痕。AI 派单在 **供应链数据专员派单** 环节提供 **默认方案**，人工改后落单。

### 3.2 输入

| 输入 | 说明 |
|---|---|
| **采购需求** | 已审核通过、剩余可派单数量 > 0 |
| 需求行 | SKU、数量、需求交期 |
| **成衣厂档案** | 启用状态、擅长品类、产能标签（一期可简化为手工维护「产能权重」） |
| **历史表现** | 同款/同 SKU 历史成衣采购单：准时率、质检合格率、平均加工费（有则算，无则空） |
| **工厂负荷** | 当前未关闭成衣采购单的在产数量合计（简化为件数或单数） |
| **BOM** | 该色码 SKU 是否存在 **生效 BOM**；无 BOM **不可派单** |

### 3.3 选厂评分（可解释加权，一期默认权重）

对每个 **需求行**，对候选成衣厂 `i` 计算得分（示例）：

| 因子 | 说明 | 默认权重方向 |
|---|---|---|
| 历史合作 | 该款/SKU 最近 12 个月是否做过 | 做过加分 |
| 准时率 | 历史交期达成率 | 高加分 |
| 质量 | 历史入库质检合格率 | 高加分 |
| 负荷 | 当前在产负荷 | 过高减分 |
| 报价参考 | 历史同 SKU 均价（仅参考） | 用于展示，一期不自动写死总价 |

**硬约束**：厂停用、无 BOM、黑名单 → 排除。

### 3.4 拆单逻辑

| 场景 | 建议策略 |
|---|---|
| 需求量小或仅一家达标 | **单厂**承接全部剩余量 |
| 需求量大或交期紧 | **拆 2～N 厂**（N 上限参数，默认 2～3），按得分比例分配数量 |
| 已部分派单 | 仅对 **剩余未派量** 再算方案 |

约束：**各厂派单量之和 ≤ 需求剩余可派量**；每厂一行：成衣厂、数量、建议交期、**建议加工费总价（参考）**、默认 **BOM 版本快照**（当前生效色码 BOM）。

### 3.5 交期与加工费

| 项 | 规则 |
|---|---|
| **建议交期** | `NeedDate − 生产周期缓冲`（来自补货参数或厂默认）；不得晚于需求交期 |
| **加工费** | 一期为 **参考价**（历史均价或档案维护的「参考单价×数量」）；专员 **必须确认或修改** 后写进成衣采购单（按单总价冻结口径不变） |

### 3.6 人机协同流程

| 步骤 | 角色 | 动作 |
|---|---|---|
| 1 | 供应链数据专员 | 打开 **委外派单**，选择已审采购需求 → 点击 **「AI 生成派单方案」** |
| 2 | 系统 | 生成 **派单建议单**（关联需求 ID），展示拆分行与评分依据 |
| 3 | 供应链数据专员 | 修改厂、数量、交期、加工费 → **确认生成** → 系统创建 **一张或多张成衣采购单** |
| 4 | 供应链 | 对采购单执行 **下达** → 成衣厂协同确认（`05`） |

**不自动**：生成即下达、不经过专员确认。

### 3.7 低置信度与异常

| 情况 | 处理 |
|---|---|
| 无候选成衣厂 | 不给方案，提示「需维护厂档案或 BOM」 |
| 仅一家厂且负荷过高 | 仍出方案但 **强提示** 人工复核 |
| 历史数据不足 | 降级为「按负荷最轻 + 有合作记录优先」，标注 **低置信度** |

## 四、系统参数（建议菜单：系统设置 → 补货与派单参数）

| 参数组 | 示例项 |
|---|---|
| 动销 | 7/14/30 天权重、是否剔除促销爆单 |
| 覆盖 | 默认目标覆盖天数 `T`、安全库存天数 |
| 周期 | 默认生产周期、国内仓周期、头程周期（用于 `L`） |
| 派单 | 最多拆厂数、负荷上限、是否允许无历史价派单 |
| 任务 | 补货建议每日运行时刻、是否按店铺分批 |

## 五、单据与状态（概念名）

| 单据 | 说明 |
|---|---|
| **补货建议单** | 一次计算批次 + 多行 SKU 建议；行可采纳/忽略 |
| **采购需求** | 人工或自建议草稿创建（现有流程） |
| **派单建议单** | 绑定采购需求的一次 AI 方案；确认后生成成衣采购单 |
| **成衣采购单** | 现有委外生产订单 |

---

## 六、与库存、财务的边界

- 补货建议 **不直接改库存**；只有上架、出库、FBA 接收等执行单改库存。  
- 派单建议 **不产生应付**；对账仍以 **成衣采购单按单总价、月结** 为准。  
- **不做** 面辅料自动采购、不做 MRP 自动展料（仍由 BOM 在派单时快照供协同）。

---

## 七、一期验收要点（产品）

1. 给定 FBA 订单与库存 fixture，补货建议量 **可手算复核**。  
2. 采纳建议生成的采购需求，能走通 **组长/总监** 审批。  
3. 派单方案确认后，成衣采购单数量之和 **不超过** 需求剩余量。  
4. 任意建议均有 **依据字段** 与 **采纳人/修改记录**。
