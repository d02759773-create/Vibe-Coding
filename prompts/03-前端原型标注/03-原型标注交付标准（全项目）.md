# 原型标注交付标准（全项目）

> 自 **跨境电商 ERP · 用户与角色** 起，**所有**前端原型的业务标注均按本标准交付（写法 + 运行时 + 构建 + 上线验证）。  
> 使用 `vitamin-prototype-annotation` 时默认遵守，无需每次重复说明。

## 1. 正文写法（读者可读）

- **样板目录**：`prd-docs/跨境电商ERP/设置/用户与角色/annotations/pages/`
- **Skill**：`references/writing-standard.md`
- **提示词**：`02-生成原型标注.md`

要点：中文页名、表格、原文 Toast；不写规范编号/枚举码/hash 当主文；跨页 `global` + 各页 `page-global`；待确认单独成句。

## 2. 角标与阅读方式（统一用 annotation-kit，禁止自造）

全项目原型上的业务规则提示，**只**用 `vitamin-prototype-annotation` 这一套 UI，与跨境 ERP 用户与角色线上一致：

| 能力 | 标准形态 |
| --- | --- |
| **工具栏** | 底栏：**标注开关**（开启后按钮深色底 + 眼睛图标）· **本页规则** · **全屏查看**；可贴边收起，默认可展开 |
| **区域角标** | 打开 **标注开关** 后，在已配置的 `type: element` 区域右上角出现 **橙色圆角数字角标**（`vpa-badge`，当前页从 1 起编号）；**纯净演示**（关闭标注）时不显示角标 |
| **点开角标** | 抽屉/浮层展示该块读者可读说明；**本页规则** / **全屏查看** 看页级与跨页规则 |
| **禁止** | 在 React/Vue 业务组件里自写「说明角标」、用 Ant Design `Badge`/`Tooltip` 顶替 PRD 标注、或换一套非 `annotation-kit` 的标注皮肤 |

接入要求：每个需要角标的区域在 config 里配 `target.selector`（优先稳定 `data-anno`）；列表/表单/详情按模块拆 `element` 块，保证主要区块都有角标可读。样式以 skill `assets/annotation-kit/runtime.css` 为准，**不要**为单项目改角标颜色/形状（除非全仓库统一升级 kit）。

## 3. 标注结构与编译

- PRD 同级 `annotations/`：`pages/*.md` + `*.annotation.config.json` +（多页模块）`annotation.workspace.json`
- 只用 `markdownFile` + `blockId`；编译产物进 `public/annotation-kit/`
- **禁止**只更新 `public` 不更新线上实际读的 `dist/annotation-kit/`（Vite 项目以 **构建后的 dist** 为准）

## 4. 运行时（必须用当前 kit）

安装/更新标注时，使用 skill 内 **最新** `assets/annotation-kit/`（含 `runtime.js` / `runtime.css`），至少包含：

| 能力 | 说明 |
| --- | --- |
| Hash 子路径部署 | `currentRouteCandidates()` 必须把 `#/route` 本身加入匹配（`index.html#/settings/roles` 场景） |
| 工具栏默认 | workspace `runtime.toolbarExpanded: true`（可配合 `toolbarDocked: true`），首次即显示 **标注开关 · 本页规则 · 全屏查看** |
| HTTP 加载 | 以 `annotation.bundle.json` 为准；编译结果内嵌 `markdown`，不依赖线上拉取 PRD 源 md |

参考实现：`front-prototype/跨境ERP/public/annotation-kit/runtime.js`、`annotations/annotation.workspace.json`

## 5. Vite 构建（推荐与跨境 ERP 一致）

```json
"build:annotations": "python tools/annotation/compile_annotations.py annotations/annotation.workspace.json",
"build": "npm run build:annotations && … && vite build"
```

`vite.config.ts` 对以下资源加 **`?v=<buildId>-<runtimeHash>`**（见 `front-prototype/跨境ERP/vite.config.ts`）：

- `annotation-kit/runtime.css`
- `annotation-kit/runtime.js`
- `annotation-kit/annotation.bundle.inline.js`

避免 CDN/浏览器长期缓存旧工具栏或旧 bundle。

## 6. 上线验收（不过不交付）

在 **最终访问 URL**（含子路径、中文目录）至少检查一页列表 + 一页表单/详情：

1. 工具栏有 **本页规则**（不是只有标注开关 + 全屏查看）
2. 打开 **标注开关** 后，主要区块出现 **橙色数字角标**（与跨境 ERP 同款）；关闭标注后角标消失
3. 点击角标弹出说明；**本页规则** / 跨页规则内容正确
4. 查看网页源代码：`runtime.js?v=` 与本次构建一致
5. 可选：`VitaminAnnotations.diagnostics()` 无大面积 `out-of-context`

## 7. 不要学的旧样

- 进销存 **采购订单** 时期那种内部编号体正文（仅作反例）
- 未合 hash 路由匹配的旧 `runtime.js`
- 只推 Git、不上传 **dist** 却期望静态站更新
