# 执行要求

## 1. 使用浏览器自动化抓取（多Space并行处理）

从帮助中心入口开始，通过页面导航、目录、站内搜索、分页和页面内链接发现资料。

只访问公开且正常可访问的页面。遵守网站的访问限制，不绕过登录、验证码、权限或其他访问控制。遇到无法访问的页面，记录 URL、页面标题（如可见）和失败原因。

优先使用产品官方帮助中心。若官方页面链接到官方 API 文档、集成文档或其他官方资料，可以纳入调研，但要标明资料类型和来源。第三方内容不得作为产品功能事实的依据。

## 2. 一边抓取，一边解析

每发现一页，先保存可见的页面内容和来源信息，再解析该页。不要只保存总结，也不要把多页内容合并后丢掉页面级来源。

为每页分配稳定的来源编号。至少记录：
- 来源编号
- 页面标题
- 页面 URL
- 帮助中心目录或面包屑路径
- 页面类型（操作说明、配置说明、API、集成说明等）
- 抓取日期
- 抓取状态（已抓取、已解析、重复、失败）
- 失败原因或备注

保留原文的结构和关键信息，不要为了精简而改写成无法核对的摘要。若无法保存完整页面内容，要明确记录实际保存范围。

## 3. 严格区分证据与判断

- 手册明确写出的内容标为“手册事实”。
- 根据多处手册内容归纳出的规律标为“归纳”。
- 你提出的产品启示或设计判断标为“分析建议”。
- 手册没有说明、页面无法访问或证据互相矛盾的内容标为“待确认”。

每条重要事实都要附来源编号、页面标题、URL，以及对应的小节或页面位置。必要时可附短句作为证据，但不要用大段原文代替分析。

没有在已检查资料中找到某能力时，写“在已检查资料中未找到相关说明”，不要直接写成“不支持”。只有手册明确说明限制、版本差异或适用条件时，才描述为产品限制、可选能力或特定套餐能力。

不得根据行业常识、页面按钮名称或相似产品的行为，补全手册未说明的业务规则、状态变化、库存影响、权限边界、费用计算或接口机制。

# 页面解析结构

对每项识别到的能力，尽量提取以下内容；手册未说明的项目写“原文未说明”：

- 能力名称
- 所属模块
- 使用场景
- 操作角色
- 前置条件、配置或依赖
- 操作流程及系统响应
- 涉及的业务对象、单据及对象关系
- 关键字段、字段含义和可选值
- 状态及状态变化
- 对订单、库存、费用或外部系统的影响
- 校验规则、异常情况和处理方式
- 权限或适用范围
- 对应来源编号和证据位置
- 尚未确认的问题

建议重点检查以下模块；这只是检索目录，不代表产品一定具备这些能力：

- 入库预约、收货、质检、上架
- 库存查询、库位管理、移库、盘点、补货
- 出库订单、分配、波次、拣货、复核、包装、发货
- 退货和异常处理
- 多货主、客户门户、仓租或操作费用
- 物流商、平台、ERP 和其他系统集成
- 商品、仓库、库区、库位等基础资料
- 策略、规则、权限和系统配置
- 报表、移动端、PDA、API

按页面中实际出现的内容组织资料，不要为了填满目录而补写不存在的能力。
