## 二、功能依赖关系

```text
DF11 预置初始化
  → DF01 类型列表
  → DF02/DF03 类型维护
  → DF05 或 DF06 项维护（依赖已选类型）
  → DF07/DF08 项 CRUD 与启停
  → DF10 对外选项查询（依赖项数据）

DF04 禁用类型 ──依赖──► DF10（需定义禁用类型的 API 行为）

下游模块（商品档案、客户档案、业务单据）
  ──依赖──► DF10（只读消费，不在字典模块写业务规则）
```

**建议 PRD 套件顺序**：字段清单（类型 + 项）→ 主 PRD → Demo PRD → 前端 `#/master/dictionaries`（当前为占位页）。

## 三、暂不进入本期的功能

| 功能 | 不进入本期原因 | 后续触发条件 |
| :--- | :--- | :--- |
| 字典批量导入/导出 | 一期量小，手工维护即可 | 初始化迁移、大批量运维 |
| 字典版本与生效日期 | 复杂度高 | 多组织、多政策并行 |
| 字典项多语言 | 一期单语中文 | 跨境或多语言 UI |
| 与财务科目/税码映射 | 超出进销存基础资料边界 | 财务模块立项 |
| 字典变更审批 | 配置类无需审核 | 强合规行业 |
| 自动同步外部主数据 | 无外部 MDM | 对接 ERP 主数据项目 |
| 用字典完全替换所有模块硬编码枚举 | 需分模块改造与迁移 | 各模块 PRD 分批挂载 |

## 需求设计自检

1. **是否只做了需求设计？** ✅ 未写字段清单与前端页面规格。  
2. **P0 是否聚焦「类型 + 项 + 启停 + 对外查询」？** ✅ DF01–DF03、DF05–DF08、DF10–DF11 为主链路。  
3. **是否守住了不做档案、不做审批的边界？** ✅ 见需求规格说明书 §三。
