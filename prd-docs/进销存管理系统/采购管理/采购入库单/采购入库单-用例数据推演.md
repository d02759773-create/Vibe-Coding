# 采购入库单-用例数据推演

> **版本**：V1.0 | 2026-10-07  
> **定位**：以采购入库单为主视角，用与《采购订单-用例数据推演》相同的数值跑通「分批入库 + 破损拒收 + PO 缺量关闭」场景，验证字段计算、状态与联动是否自洽。  
> **读者**：PM 自检、评审、测试用例素材  
> **前置**：采购订单 `PO20260602-0001` 已审核通过（待入库 → 经第一次入库后部分入库），商品 SKU001、100 件 @ 50.00 元含税、税率 13%。

---

## 一、推演场景描述

**业务背景**：仓管老李按采购订单收货。第一批 40 件全合格；第二批实收 60 件、合格 55 件、运输破损 5 件；之后采购员对 PO 缺量完结，本场景**不**再创建第三张入库单。

**涉及单据**：采购入库单 `GR20260605-0001`、`GR20260610-0001`；应付记录 ×2；采购订单回写。

**不涉及**：采购退货、已入库作废、付款登记。

## 三、分步推演

### 步骤 1：创建第一张入库单（草稿）

**操作**：2026-06-05 到货 40 件。老李从 PO 详情点击「创建入库单」，系统生成草稿。

**入库单头部（创建后）**：

| 字段 | 值 | 说明 |
|---|---|---|
| 入库单号 | GR20260605-0001 | 系统生成 |
| 关联采购单号 | PO20260602-0001 | 锁定 |
| 供应商 | GYS001 深圳华强电子 | PO 快照 |
| 入库仓库 | CK001 深圳总仓 | PO 快照 |
| 入库日期 | 2026-06-05 | 默认当天 |
| 单据状态 | 草稿 | |
| 确认阻断 | false | |

**明细行**：

| 商品编码 | 参考未入库数量 | 本次实收数量 | 本次入库数量 | 破损拒收数量 | 单价（含税） |
|---|---|---|---|---|---|
| SKU001 | 100 | （待填） | （待填） | 0 | 50.00 |

**老李录入**：实收 40、入库 40。

**系统计算（保存前）**：
- 破损拒收数量 = 0
- 入库金额（含税）= 40 × 50.00 = **2,000.00**

**状态**：仍为草稿。

**联动**：无（未确认）。

### 步骤 2：确认第一张入库单

**操作**：老李点击「确认入库」。

**校验**：
- 40 ≤ 未入库 100 ✅
- 40 ≤ 实收 40 ✅
- 至少一行入库 > 0 ✅

**入库单变更**：

| 字段 | 变更前 | 变更后 |
|---|---|---|
| 单据状态 | 草稿 | **已入库** |
| 本次入库总数量 | — | **40** |
| 入库总金额（含税） | — | **2,000.00** |
| 确认人 | — | 老李 |
| 确认时间 | — | 2026-06-05 10:20:00 |

**采购订单回写**：

| 字段 | 变更前 | 变更后 |
|---|---|---|
| 订单状态 | 待入库 | **部分入库** |
| 累计已入库数量 | 0 | **40** |
| 未入库数量 | 100 | **60** |

**下游**：
- 库存：CK001 / SKU001 **+40**
- 应付：**2,000.00** 元（含税），关联 GR20260605-0001

### 步骤 3：创建第二张入库单（草稿）

**操作**：2026-06-10 第二批到货。老李再次「创建入库单」。

| 字段 | 值 |
|---|---|
| 入库单号 | GR20260610-0001 |
| 关联采购单号 | PO20260602-0001 |
| 单据状态 | 草稿 |

**明细（创建时参考未入库）**：

| 商品编码 | 参考未入库数量 | 本次实收数量 | 本次入库数量 | 破损拒收数量 | 差异原因 |
|---|---|---|---|---|---|
| SKU001 | **60** | 60 | 55 | **5**（系统算） | 运输破损 |

**校验（保存/确认前）**：
- 入库 55 ≤ 未入库 60 ✅
- 入库 55 ≤ 实收 60 ✅
- 破损 5 = 60 − 55 ✅

**系统计算**：
- 入库金额（含税）= 55 × 50.00 = **2,750.00**
- 破损 5 件对应潜在金额 250.00 **不进入应付**

## 四、关键验证点

### 验证 1：数量闭环（合格入库口径）

```
PO 采购 100 = GR1 入库 40 + GR2 入库 55 + PO 放弃未入库 5
```

破损 5 件不计入 PO 累计已入库。✅

### 验证 2：金额与应付（R22）

| 单据 | 本次入库数量 | 含税金额 | 应付 |
|---|---|---|---|
| GR20260605-0001 | 40 | 2,000.00 | 2,000.00 |
| GR20260610-0001 | 55 | 2,750.00 | 2,750.00 |
| **合计** | **95** | **4,750.00** | **4,750.00** |

PO 订单金额 5,000.00 元；应付合计 4,750.00 元，与合格入库一致。✅（主 PRD R22）

### 验证 3：入库单状态机

```
草稿 → 已入库（每张 GR 各一次）
草稿 → 删除（阻断场景下的残留草稿）
```

无「已入库 → 草稿」回退。✅

### 验证 4：快照

| 路径 | 字段 | 验证 |
|---|---|---|
| PO → GR | 单价 50.00 | 确认后改商品档案价，GR 仍为 50.00 ✅ |
| PO → GR | 供应商/仓库 | 档案停用后历史 GR 展示不变 ✅ |

### 验证 5：超收反例（未在本故事执行，规则校验）

若 GR2 填入库 **61**（未入库当时为 60）→ 确认阻断。与主 PRD R08、PO R25 一致。
