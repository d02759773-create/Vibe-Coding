## 零、通用交互与校验（继承 context/12）

> **权威源**：`context/跨境电商ERP/12-前端通用交互与表单校验（一期）.md`。

| context/12 条款 | 本套件表单页落点 |
| :--- | :--- |
| §一 保存与跳转 | **新增**用户/角色保存成功 → Toast「**新增成功**」→ **返回对应列表**（`/settings/users`、`/settings/roles`）。**编辑**保存成功 → Toast「**保存成功**」→ **返回列表**（本模块 Demo 统一回列表，不进详情/编辑停留） |

| §二 Toast | 成功用 `message.success`；业务阻断用 `message.error`；全表校验未通过额外 `message.warning`「**请完善标红字段后再保存**」 |

| §三 规则分层 | 字段规则见字段清单与 G-PHONE-REGEX；业务规则见主 PRD（ADMIN 保底、角色重复行等）；**启停用状态**不在表单内修改 |
| §四 列表筛选 | 不适用本文件；见《用户与角色_Demo_列表页》§零 |

## 二、用户新增 / 编辑页

### 2.1 页面目标

录入用户头部字段与子表「用户已分配角色明细」；保存后默认 `启停用状态=ENABLED`（新增）；不在表单内改启停状态。

### 2.2 骨架

页头（标题：新增用户 / 编辑用户）→ 表单卡片（基本信息 + 已分配角色）→ **底栏**（表单区域底部右对齐，与进销存表单一致；非 viewport 吸底 **[P2]**）。

### 2.3 底栏按钮

| 按钮 | 样式 | 说明 |
| :--- | :--- | :--- |
| 返回列表 | 次 | 回 `/settings/users`；**[P2]** 有未保存变更时 `Modal.confirm` 二次确认 |
| 保存 | 主 | 校验通过后提交；点击后 **loading** 至请求结束，防重复点击（context/12） |

无「保存并提交」（无审核流）。

### 2.4 卡片一：基本信息

桌面端 **2 列**栅格（`ProForm` grid）；窄屏 1 列。**一期原型**可用单列 horizontal 布局，字段顺序不变。

| 字段 | 新增 | 编辑 | 控件 | 规格 |
| :--- | :--- | :--- | :--- | :--- |
| 用户账号 | 可编辑 | **只读** | `Input` | placeholder「2-32 位登录名」；编辑态 ReadonlyText |
| 用户姓名 | 可编辑 | 可编辑 | `Input` | 必填；去首尾空格 |
| 手机号 | 可编辑 | 可编辑 | `Input` | 选填；有值时 **G-PHONE-REGEX**（文案：`请输入有效的手机号或座机号`） |
| 邮箱 | 可编辑 | 可编辑 | `Input` | 选填；**有值时**标准邮箱格式；失焦或保存失败：标红 +「请输入有效的邮箱地址」 |
| 用户备注 | 可编辑 | 可编辑 | `Textarea` | 0–200 字 |

**不展示**：`启停用状态`、`停用原因`、`已分配角色摘要`、`最后登录时间`、系统字段。

### 2.5 卡片二：角色分配

标题：**已分配角色**。

**工具条**：`添加角色`（打开行内空行或下拉选角色）。

**子表列**：

| 列 | 控件 | 说明 |
| :--- | :--- | :--- |
| 角色编码 | `SelectWithSearch` | 仅可选 `启停用状态=ENABLED` 的角色（**预置 + 自定义**）；展示 `{角色编码} {角色名称}`；同一编码不可重复行 |
| 角色名称 | ReadonlyText | 选编码后带出 |
| 操作 | 文字「移除」 | 删除该行 |

- 允许 **0 行**（主 PRD R02）
- 保存时若 **编辑** 导致无任一启用用户持有 `ADMIN`（且当前用户为最后一员）：阻断，Toast「须至少保留一名启用的管理员账号」
- **新建用户**不要求必须分配 `ADMIN`（主 PRD R05 澄清）；修正输入后字段红字即时消除

### 2.6 校验与反馈（落实 §零 / context/12 §三）

| 场景 | 行为 |
| :--- | :--- |
| 必填为空 / 格式错误 | 字段标红 + 红字；Toast「请完善标红字段后再保存」 |
| 用户账号重复 | `用户账号` 标红「用户账号已存在」+ Toast 同文案 |
| 手机号非法 | 标红 +「请输入有效的手机号或座机号」（G-PHONE-REGEX） |
| 邮箱非法 | 标红 +「请输入有效的邮箱地址」 |
| 角色子表重复编码 | Toast「同一角色不可重复添加」 |
| ADMIN 保底 | Toast「须至少保留一名启用的管理员账号」 |
| 新增保存成功 | Toast「新增成功」→ `/settings/users` |
| 编辑保存成功 | Toast「保存成功」→ `/settings/users` |

## 四、角色菜单权限配置页

### 4.1 路径与目标

`/settings/roles/:roleCode/permissions` — 配置「角色菜单权限明细」；**仅二级** `菜单可见性`。

### 4.2 页头信息（只读）

展示 `角色编码`、`角色名称`（便于识别）。

### 4.3 权限表（推荐布局）

- 数据源：与 `sidebarMenu.ts` 二级菜单一致
- **单表三列**（`tableLayout: fixed`）：`一级菜单`（同组首行 rowSpan 合并）｜`二级菜单`｜`菜单可见性`
- `菜单可见性` 列 **固定宽度、居中**，保证 Switch 纵向对齐
- 可编辑列：`Switch`（开=`VISIBLE`，关=`HIDDEN`）或等价 Select
- 备选：按一级菜单分 Card + 子表（需同样固定「菜单可见性」列宽，不推荐）

**不展示**：`数据范围说明`、按钮级权限。

**批量（可选 Demo 简化）**：一级下「全选可见 / 全选隐藏」为体验增强，不改变字段模型。

### 4.4 底栏

`返回` + `保存`（主，保存时 loading）；保存成功 Toast「权限已保存」并 **停留本页**（context/12 §一 模块例外）；失败不跳转。

### 4.5 侧栏预览（可选）

Demo 可不实现；权限变更按主 PRD **即时生效**（刷新菜单或重新拉取权限即可，不强制重新登录）。
