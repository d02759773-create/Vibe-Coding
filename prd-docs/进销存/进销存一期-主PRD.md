## 一、业务背景

目标用户为**境内批发/贸易企业**（练手默认参照 `product-design-docs` 中强盛科技：代理商电话/微信下单、内勤录单、仓库按单发货、财务登记回款）。

一期要解决：采购与销售意图有单可查、出入库改库存有凭据、客户/供应商欠款说得清，避免「口头下单、库存靠记、财务事后补账」。

---

## 二、功能范围

### In Scope

| 域 | 能力 |
|---|---|
| 基础资料 | 商品、客户、供应商、仓库（启停用，无物理删除） |
| 采购 | 采购订单；采购入库单（分批入库）；采购订单状态与数量追踪 |
| 销售 | 销售订单；销售出库单（分批出库）；审核后占用可用库存 |
| 库存 | 按仓库+SKU 的现存/占用/可用；库存流水（入/出/占用/释放） |
| 往来 | 入库形成应付、出库形成应收；收款单/付款单及手工核销 |
| 查询 | 订单/出入库列表；库存余额；客户欠款、供应商应付（基础） |
| 系统 | 用户登录（可简化）、单据编号、操作日志（可简化）、期初库存/期初往来（含初始化） |

### Out of Scope

- 电商平台订单同步、零售收银、PDA 扫码拣货
- 采购计划/自动补货、多级审批、合同价管理
- 信用额度硬拦截、银行流水自动认款
- 完整总账、凭证、成本精细分摊（可做行级毛利展示，不做财务总账）
- 多仓调拨、盘点、报损（建议二期；若一期要「库存绝对可信」可加**盘点单**为 P1）
- 与跨境 ERP、海外 WMS、SRM 的 API 对接

## 三、单据定位（系统级）

### 3.1 两层架构

| 层级 | 采购侧 | 销售侧 | 库存变动 |
|---|---|---|---|
| 计划层 | 采购订单 | 销售订单 | 销售订单**审核**仅**占用**，不扣现存 |
| 执行层 | 采购入库单 | 销售出库单 | **确认入库/出库**时改现存，并处理占用/应付/应收 |

### 3.2 状态机原则

- 状态变更仅通过**动作按钮**（审核、驳回、下推、确认入库/出库、作废、缺量完结等）
- 审核后关键字段锁定；商品明细为**快照**
- 主数据停用后不可被新单引用

详细状态以各单据主 PRD 为准（采购订单、销售订单已定稿）。

### 3.3 库存三口径（经营底账）

| 口径 | 含义 | 典型触发 |
|---|---|---|
| 现存 OnHand | 账面在库数量 | 入库确认 +N；出库确认 −N |
| 占用 Reserved | 已被销售订单锁定 | 销售订单审核 +占用；出库确认或缺量完结 −占用 |
| 可用 Available | 可再承诺量 | 现存 − 占用（同仓库同 SKU） |

采购订单**不**预占库存（一期惯例：以到货入库为准）；若需「在途」为四口径，列为二期。

## 四、业务场景（一期必覆盖）

| 编号 | 场景 | 主路径 |
|---|---|---|
| S1 | 向供应商订货 | 新建采购订单 → 审核 → 到货创建采购入库单 → 确认入库 |
| S2 | 向客户批发销售 | 新建销售订单（看欠款/可用提醒）→ 审核占库存 → 创建销售出库单 → 确认出库 |
| S3 | 分批发货/分批到货 | 同一订单多次下推入库/出库，累计数量回写订单行 |
| S4 | 缺量完结 | 采购/销售订单未执行完毕时人工关闭剩余数量 |
| S5 | 客户回款 | 财务创建收款单，勾选应收核销 |
| S6 | 供应商付款 | 财务创建付款单，勾选应付核销 |
| S7 | 期初上线 | 录入期初库存、期初应收/应付，再启用日常单据 |

**P1（建议紧跟 P0）**：采购退货、销售退货；发货短少/漏发登记（见销售需求 SF09/SF10）。

## 六、上下游联动规则（摘要）

1. **采购订单审核** → 允许创建采购入库单，不改库存。  
2. **采购入库确认** → 现存 +N；生成应付（或按企业习惯记应付）。  
3. **销售订单审核** → 校验可用量，占用 +N。  
4. **销售出库确认** → 现存 −N、占用 −N；生成应收。  
5. **收款核销** → 应收余额减少；允许多笔应收一笔收款。  
6. **停用商品/客户/供应商** → 不影响历史单据展示，禁止新单引用。

## 八、验收标准（一期）

1. 任选 SKU：手工推演 S1+S2 后，`现存、占用、可用` 与流水一致。  
2. 销售订单审核后，可用量减少、占用增加；出库后现存与占用同步减少。  
3. 出库后客户应收余额正确；收款核销后欠款减少。  
4. 入库后供应商应付正确；付款核销后应付减少。  
5. 所有状态变更在 UI 上仅能通过按钮触发，无表单直改状态。

## 十、建议的「本周第一步」

1. **补客户档案 PRD 三件套**（当前仓库内缺失，但销售订单已依赖客户）。  
2. **写采购入库单主 PRD**（打通「进」的执行层与库存 +N）。  
3. 用 `prompts/课程6-*` 或 `prompts/PRD生成-业务单据.md` 按模板批量产出字段清单与 Demo 三页。

完成以上三步后，即可开始进销存前端壳与「采购订单 → 入库」联调原型。
