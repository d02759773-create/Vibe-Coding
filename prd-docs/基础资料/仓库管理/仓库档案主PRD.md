# 仓库档案主PRD

> **版本**：V2.0 | 2026-09-30  
> **读者**：产品经理、前端工程师、测试工程师  
> **说明**：仓库档案为腾达科技跨境电商 ERP 的 **主数据 CRUD**，统一 **实体仓 + 逻辑仓** 的识别口径与库存分区角色。字段定义以《仓库档案字段清单》为准；业务流程见《仓库档案-业务流程推演》。

---

## 1. 业务背景

腾达科技在东莞设有国内仓（收货、质检、压气、贴标、发货），并与合作方设有海外仓（TK、Walmart 等）。采购入库、质检分流、发货出库等链路都依赖 **「进哪个逻辑仓、从哪个逻辑仓扣库存」** 的准确识别。

若仓库主数据只有「一个仓名」、不区分实体仓与逻辑仓，会出现：

- 待检、良品、不良品库存混在一起，可发数量不清；
- 国内仓与海外合作仓账实混淆；
- 采购入库、出库单据无法稳定引用同一套仓库编码。

因此，仓库档案的目标是：**统一实体场地与逻辑库存分区的识别信息**，并约束下游单据如何选用仓库（见 §8）。

**业务决策锚点**（推演 D-01～D-10）：国内合格可发库存 **仅在良品逻辑仓**；平台（Amazon FBA / TikTok / Walmart）在货件计划与出库单的 **目标平台** 字段区分，**不设**国内渠道逻辑仓；一期出库只扣源逻辑仓、不记在途；停用前库存须为 0。

## 2. 功能范围

**In Scope**

- 实体仓档案维护（国内 / 海外类型）
- 逻辑仓档案维护（归属实体仓、逻辑仓类型）
- 启用 / 停用管理（含停用原因、库存为 0 校验）
- 列表、新增、编辑、详情
- 实体仓详情展示下属逻辑仓数量等汇总（字段见字段清单 §三）

**Out of Scope**

- 库位管理、批次/效期
- 国内渠道逻辑仓（AMZ/TK/WMT 分桶，已废止，D-10）
- 头程在途逻辑仓 `IT` 一期建档与记账（D-01，后续期）
- 海外仓完整出入库流水（一期海外逻辑仓仅建档，D-04）
- 库存数量维护（由出入库单据驱动，不在档案表单改数）
- 复杂仓网规划、与平台/WMS API 同步
- 审批流（提交/审核）；本模块 **无单据审核态**，仅启停用
- 物理删除档案

## 3. 模块定位

| 项目 | 内容 |
| :--- | :--- |
| 单据定位 | **主数据**；非业务流转单据，无审核状态机 |
| 模块类型 | 主数据 CRUD（实体仓 + 逻辑仓两类档案） |
| 核心职责 | 统一仓库编码、层级（实体/逻辑）、质量态逻辑仓类型、启停与下游可选范围 |
| 直接服务 | 采购入库（入待检）、质检结果、发货出库（国内源仓=良品）、库存查询、采购退货（不良品） |
| 状态管理 | **启停用状态** `ENABLED` / `DISABLED`（`AGENTS.md`：状态变更仅能通过动作按钮触发） |

## 4. 典型业务场景

| 场景ID | 场景 | 类型 | 说明 |
| :--- | :--- | :--- | :--- |
| S01 | 新建国内实体仓 | 主流程 | 如 `PHY-CN-DG` 东莞仓，`DOMESTIC` |
| S02 | 在国内实体下新建逻辑仓 | 主流程 | 待检 / 良品 / 不良品（一期国内必建三态） |
| S03 | 新建海外实体仓与逻辑仓 | 主流程 | `PHY-US-3PL` + `US_TK` / `US_WMT`；一期仅建档 |
| S04 | 维护地址与负责人 | 主流程 | 不影响历史单据快照 |
| S05 | 停用逻辑仓 | 辅助 | 库存合计必须为 0（D-09）；填停用原因 |
| S06 | 停用实体仓 | 辅助 | 下属逻辑仓库存均为 0；建议先停逻辑仓 |
| S07 | 恢复启用 | 辅助 | 停用仓可重新在新单中选择 |
| S08 | 历史仓追溯 | 辅助 | 已停用仓在历史单据、库存查询仍可见 |

## 5. 模块级通用规则

| 规则ID | 规则 |
| :--- | :--- |
| R01 | **仓库编码**（实体仓、逻辑仓）全局唯一；一旦被库存或业务单据引用后 **不可修改**。 |
| R02 | 实体仓必填：编码、名称、实体仓类型、地址、负责人；逻辑仓必填：编码、名称、归属实体仓、逻辑仓类型。字段必填性以《仓库档案字段清单》为准。 |
| R03 | 新增档案默认 **启用**；新增/编辑表单 **不展示** `启停用状态` 下拉，仅通过「启用」「停用」动作变更。 |
| R04 | **停用**须填写 `停用原因`；**逻辑仓**停用前本仓 `当前库存数量合计` 必须为 0；**实体仓**停用前下属逻辑仓库存合计须为 0（D-09）。 |
| R05 | 停用仓库 **不可**在新建采购、入库、出库、调拨等业务单据中选择；历史单据仍展示原仓库信息。 |
| R06 | 主数据 **不提供删除**；不再使用统一「停用」。 |
| R07 | 保存后一期 **不可修改**：实体仓 `实体仓类型`；逻辑仓 `归属实体仓`、`逻辑仓类型`。纠错策略：停用旧档案 + 新建正确档案。 |
| R08 | 逻辑仓类型与能力由系统派生：`是否允许采购入库`、`是否允许出库拣货`（字段清单）；用户不可手工改。 |
| R09 | 国内 `DOMESTIC` 实体下逻辑仓类型仅允许 `QC` / `GOOD` / `DEF`（一期）；海外 `OVERSEAS` 下允许 `US_TK` / `US_WMT`。`IT` 一期不可选。 |
| R10 | **D-10**：国内仅 **良品仓** 可作为发货出库源仓；Amazon / TikTok / Walmart 不在仓库档案用独立逻辑仓表达。 |

## 6. 状态与动作规则

### 6.1 启停用状态

| 状态 | 含义 |
| :--- | :--- |
| 启用 `ENABLED` | 可在新业务单据的仓库选择器中被引用（须同时满足类型能力，如采购入库仅 `QC`） |
| 停用 `DISABLED` | 不可在新业务单据中选择；历史数据保留 |

### 6.2 动作矩阵

| 动作 | 启用 | 停用 | 说明 |
| :--- | :---: | :---: | :--- |
| 查看 | ✅ | ✅ | 列表、详情 |
| 编辑 | ✅ | ✅ | 受 R01、R07 约束 |
| 停用 | ✅ | ❌ | 弹窗填原因；校验库存（R04） |
| 启用 | ❌ | ✅ | 确认后恢复 |
| 删除 | ❌ | ❌ | 不提供 |

## 7. 动作级规则

### 7.1 新增实体仓

| 规则ID | 规则 |
| :--- | :--- |
| A01 | 选择建档类型为 **实体仓** 后，展示实体仓字段组（字段清单 §一）。 |
| A02 | 编码唯一性校验失败则阻断保存。 |
| A03 | 保存后 `仓库层级` 固定为 `PHYSICAL`，`启停用状态` 默认为 `ENABLED`。 |

### 7.2 新增逻辑仓

| 规则ID | 规则 |
| :--- | :--- |
| A11 | `归属实体仓` 仅可选 **启用** 的实体仓；保存后不可改归属。 |
| A12 | `逻辑仓类型` 选项受实体仓类型过滤（R09）；保存后不可改类型。 |
| A13 | 选择归属实体仓后自动写入 `归属实体仓名称` 快照。 |
| A14 | 根据 `逻辑仓类型` 自动写入 `逻辑仓类型说明`、`是否允许采购入库`、`是否允许出库拣货`。 |

### 7.3 编辑

| 规则ID | 规则 |
| :--- | :--- |
| A21 | 已引用仓库的 **编码** 不可编辑。 |
| A22 | 停用状态下仍允许编辑非锁定字段（名称、地址、备注等）。 |

### 7.4 停用 / 启用

| 规则ID | 规则 |
| :--- | :--- |
| A31 | 停用必须通过 **停用** 动作按钮；弹窗内 `停用原因` 必填。 |
| A32 | 逻辑仓：库存合计大于 0 时阻断停用，提示先出库/调整。 |
| A33 | 实体仓：下属任一逻辑仓库存合计 &gt; 0 时阻断停用（或提示先处理下属仓）。 |
| A34 | 启用无需填原因；记录 `启用人`、`启用时间`。 |

## 8. 下游引用影响规则

| 引用模块 | 引用对象 | 说明 |
| :--- | :--- | :--- |
| 采购入库 | 逻辑仓 `QC`（待检） | 仅 `是否允许采购入库=true`；D-08 不允许直入良品 |
| 质检结果 | `QC` → `GOOD` / `DEF` | 转移库存分区，非本模块表单操作 |
| 发货出库（国内） | 逻辑仓 `GOOD` | 源仓固定或限定良品；**目标平台**在出库单维护 |
| 采购退货出库 | 逻辑仓 `DEF` | 不良品退供 |
| 库存查询 | 实体仓 + 逻辑仓 + SKU | 实时读档案名称；停用仓可查历史余额 |
| 海外出入库 | `US_TK` / `US_WMT` | **一期不实现**；档案预置 |

**快照规则**：下游单据固化 `仓库编码`、`仓库名称`、`逻辑仓类型` 等，详见字段清单 §五；档案后续改名不影响历史单。

## 9. 异常与边界规则

| 场景 | 处理口径 |
| :--- | :--- |
| 仓库编码重复 | 阻断保存，提示「仓库编码已存在」 |
| 停用时未填原因 | 阻断停用 |
| 停用时库存不为 0 | 阻断停用，提示当前库存合计 |
| 已引用仓库改编码 | 阻断，提示已被业务单据引用 |
| 逻辑仓类型与实体仓类型不匹配 | 阻断保存，如国内实体不得选 `US_TK` |
| 名称重复、编码不同 | 一期允许，建议人工确认 |
| 试图在表单改启停用状态 | 不提供该控件 |

## 11. 反馈与验收重点

### 11.1 关键反馈

| 操作 | 反馈方式 | 文案 |
| :--- | :--- | :--- |
| 保存成功 | Toast | 保存成功 |
| 启用成功 | Toast | 启用成功 |
| 停用成功 | Toast | 停用成功 |
| 编码重复 | 字段红字 | 仓库编码已存在 |
| 已引用不可改编码 | Toast | 该仓库已被业务单据引用，编码不可修改 |
| 停用库存未清零 | Toast | 当前仓库仍有库存，请先处理后再停用 |
| 停用原因为空 | 弹窗红字 | 停用原因不能为空 |

### 11.2 验收重点

| # | 验收项 | 验收标准 |
| :--- | :--- | :--- |
| V01 | 编码唯一 | 实体仓、逻辑仓编码均全局唯一 |
| V02 | 实体/逻辑分层 | 逻辑仓必须归属实体仓；列表可区分层级 |
| V03 | 类型约束 | 国内仅 QC/GOOD/DEF；海外 US_TK/US_WMT；一期无 IT、无国内 AMZ/TK/WMT |
| V04 | 能力派生 | 仅 QC 可采购入库；国内仅 GOOD 可出库拣货 |
| V05 | 锁定字段 | 引用后编码不可改；类型/归属保存后不可改 |
| V06 | 启停用路径 | 仅动作按钮改状态；新增不展示状态字段 |
| V07 | 停用校验 | 库存非 0 不可停用；须填停用原因 |
| V08 | 无删除 | 全链路无删除入口 |
| V09 | 与字段清单一致 | 页面字段、枚举与《仓库档案字段清单》V2.1 一致 |
