# 仓库档案-用例数据推演

> **版本**：V1.0 | 2026-09-30  
> **前置文档**：《仓库档案字段清单》V2.1、《仓库档案主PRD》V2.0、《仓库档案-业务流程推演》V1.4  
> **推演范围**：仓库主数据建档与启停用规则 **+** 依赖仓库编码的国内库存分桶闭环（采购入库→质检→发货出库）；**不验证**海外仓流水、头程在途、金额成本

---

## 一、推演目标

- 用具体编码与数量验证：
  1. **实体仓 / 逻辑仓** 建档后，下游能否正确引用且 **快照** 稳定；
  2. **国内三态**（待检 / 良品 / 不良品）库存是否 **互斥分桶、数量可加总闭合**；
  3. **D-10**：合格可发库存 **仅在良品仓**；Amazon FBA 仅体现在出库单 **目标平台**，不拆国内渠道逻辑仓；
  4. **D-09**：逻辑仓 **有库存不可停用**；库存清零后可停用；
  5. **D-05 / D-06**：短拣余量留良品仓；出库只扣源仓、不记在途。
- **场景 A**：主数据 Happy Path + 一次入库质检 + 一次全量出库（无短拣）
- **场景 B**：课堂固定案例 — 质检分流 + 货件计划 + **短拣出库** + 停用校验
- 不验证：页面控件、权限码实现、海外 `US_TK`/`US_WMT` 出入库、库内调拨纠错单细节

## 三、场景 A：建档引用 + 入库质检 + 一次全量出库

**场景描述**：采购到货 80 件，质检全部合格；货件计划 Amazon FBA 发 80 件；一次出库实发 80 件；逻辑仓停用前置校验（良品应仍有 0，不良品仓无货）。

### 3.1 推演步骤

| 步骤 | 操作/事件 | 输入数据 | 系统计算 / 字段变化 | 主数据 / 单据状态 | 库存影响（件，`WD-2025SPU01-RED-M`） |
| :---: | :--- | :--- | :--- | :--- | :--- |
| ① | 管理员已建档 | 见 §2.1 | `下属逻辑仓数量（PHY-CN-DG）= 3` | 各仓 `启停用状态=ENABLED` | 全 0 |
| ② | 采购入库审核 | 实收 **80**；入库仓=`LOG-CN-QC` | 快照：`仓库编码=LOG-CN-QC`，`仓库名称=东莞待检仓`，`逻辑仓类型=QC` | 入库单已审核 | `QC`：**0→80** |
| ③ | 质检确认 | 合格 **80**，不良 **0** | 质检单关联入库仓 | 质检完成 | `QC`：80→**0**；`GOOD`：0→**80** |
| ④ | 货件计划保存 | `目标平台=AMAZON_FBA`；计划 **80** | 不动库存 | 计划已保存 | 无 |
| ⑤ | 发货出库确认 | 源仓=`LOG-CN-GOOD`；实发 **80** | 快照源仓 GOOD；`目标平台=AMAZON_FBA` 记在出库单 | 出库单已确认 | `GOOD`：80→**0** |
| ⑥ | 校验良品仓库存合计 | — | `当前库存数量合计=0` | — | 通过 |
| ⑦ | 停用 `LOG-CN-GOOD` | 原因：「业务调整」 | `启停用状态`：ENABLED→DISABLED | 停用成功 | 无 |

> 若在步骤 ④ 后、出库前尝试停用良品仓且 `GOOD` 仍有 80，步骤应 **阻断**（同场景 B 步骤 ⑤）。

### 3.2 场景 A 库存快照

| 步骤后 | QC | GOOD | DEF | 国内合格品合计（=GOOD） |
| :--- | :---: | :---: | :---: | :---: |
| ② 入库后 | 80 | 0 | 0 | 0 |
| ③ 质检后 | 0 | 80 | 0 | 80 |
| ⑤ 出库后 | 0 | 0 | 0 | 0 |

### 3.3 场景 A 走查清单

- [x] 采购入库仅能选 `QC`
- [x] 出库源仓为 `GOOD`，平台在 `目标平台` 字段
- [x] 待检+良品+不良 数量闭合：80 件全程无丢失、无重复
- [x] 出库后良品为 0，可停用逻辑仓

**结论**：场景 A 通过。

## 四、场景 B：质检分流 + 短拣出库 + 停用阻断与不良品仓停用

**场景描述**：与《仓库档案-业务流程推演》§1.3 对齐 — 入库 100；合格 96 / 不良 4；Amazon 货件计划 60；实发 58；验证短拣留良品、不良品仓停用、有库存时停用阻断。

> **前置**：场景 A 结束后，将 `LOG-CN-GOOD` **重新启用**（便于继续出库演练）；或本场景独立期初：三逻辑仓均为启用，库存从 0 开始。

### 4.1 推演步骤

| 步骤 | 操作/事件 | 输入数据 | 系统计算 / 字段变化 | 状态 | 库存影响 |
| :---: | :--- | :--- | :--- | :--- | :--- |
| ① | 采购入库 | 实收 **100** → `LOG-CN-QC` | 入库快照 QC | 已审核 | `QC`：0→**100** |
| ② | 质检 | 合格 **96**；不良 **4** | — | 完成 | `QC`：100→0；`GOOD`：0→**96**；`DEF`：0→**4** |
| ③ | 货件计划 | `AMAZON_FBA`；计划 **60** | 不动库存 | 已保存 | 无 |
| ④ | 发货出库 | 源仓 `LOG-CN-GOOD`；计划 60；实发 **58** | 短拣 2 件留源仓（D-05） | 已确认 | `GOOD`：96→**38**（96−58） |
| ⑤ | 尝试停用良品仓 | 填原因 | `当前库存数量合计=38` | **阻断** | 提示仍有库存 |
| ⑥ | 采购退货出库（不良品） | 自 `LOG-CN-DEF` 退供 **4** | 退货单快照 DEF | 已确认 | `DEF`：4→**0** |
| ⑦ | 停用 `LOG-CN-DEF` | 原因：「无不良库存」 | 库存合计=0 | **停用成功** | 无 |
| ⑧ | 库存查询（实体仓汇总） | `PHY-CN-DG` | 在库合计=38（均在 GOOD） | — | QC=0，GOOD=38，DEF=0 |

### 4.2 场景 B 关键数量校验

| 校验项 | 公式 / 预期 | 结果 |
| :--- | :--- | :---: |
| 入库实收 | 100 | ✅ |
| 质检守恒 | 96+4=100 | ✅ |
| 出库实发 | 58 | ✅ |
| 良品结余 | 96−58=**38** | ✅ |
| 短拣未发 | 60−58=2，仍计在 **GOOD**（非回待检） | ✅ |
| 不良退供后 DEF | 0，可停用 | ✅ |
| 平台维度 | 出库单 `目标平台=AMAZON_FBA`，库存仍在 GOOD，**无**国内 AMZ 逻辑仓 | ✅ |

### 4.3 场景 B 走查清单

- [x] 短拣 2 件仍在良品仓（38 件含「未发出的 2 件」）
- [x] 有库存时不可停用 GOOD（步骤 ⑤）
- [x] DEF 清零后可停用
- [x] 货件计划 60 与实发 58 不要求库存先划到渠道仓

**结论**：场景 B 通过。

## 五、数量闭环

### 5.1 国内实体仓 `PHY-CN-DG` 分桶守恒

在任意时刻，对同一 SKU：

$$
\text{历史采购入库累计实收} = Q_{QC} + Q_{GOOD} + Q_{DEF} + Q_{\text{已出库良品}} + Q_{\text{已退供不良}}
$$

场景 B 终态（步骤 ⑧）：

| 桶 | 当前在库 |
| :--- | :---: |
| QC | 0 |
| GOOD | 38 |
| DEF | 0 |
| 已出库（良品扣减累计） | 58 |
| 已退供（不良扣减累计） | 4 |
| 闭合检查 | 0+38+0+58+4 = **100** ✅ |

### 5.2 与「良品 = 三渠道仓之和」的区分

- **D-10 下**：国内 **不存在** 亚马逊/TK/沃尔玛三个逻辑仓库存桶。
- **合格品在库** = `LOG-CN-GOOD` 当前数量（场景 B 为 38）。
- **平台计划 60、实发 58** 只影响出库单据，不拆成三个逻辑仓余额。

### 5.3 海外仓与国内良品

- `LOG-US-TK` / `LOG-US-WMT` 一期 **无流水**，库存恒为 0。
- **不得**将国内 GOOD 38 与海外逻辑仓数量相加为「公司总库存」展示（不同实体仓）；若做集团汇总，应分实体仓两行展示。

## 六、金额闭环

本套件为 **仓库主数据 + 库存数量分桶**，一期 **不核算** 库存金额、成本、应收应付。

| 维度 | 说明 |
| :--- | :--- |
| 仓库档案 | 无金额字段 |
| 库存台账 | 用例仅验证 **数量**；金额闭环在采购/成本 PRD 推演 |

**结论**：金额闭环 **不适用**；若后续增加库存成本价，需单独《库存成本用例推演》。
