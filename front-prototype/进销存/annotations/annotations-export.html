[warehouse-list:4] 启停用弹窗

warehouse-list

启用 / 停用确认弹窗

来源：《仓库档案主PRD》§5.3、§7.3（A21–A22）；《仓库档案_前端Demo版PRD》§2.2 操作列说明、§七

停用（列表行或详情入口逻辑一致）：

  1. 点击「停用」时 先 校验本仓实时库存数量合计；若 &gt; 0：Toast「当前仓库仍有库存，请先处理后再停用」，不打开弹窗。
  2. 库存 = 0 时打开弹窗；停用原因 必填，1–200 字符；未填红字「停用原因不能为空」。
  3. 成功：Toast「仓库已停用」，状态 DISABLED，写入停用人/停用时间。

启用：纯确认弹窗，无需原因；成功 Toast「仓库已启用」，更新启用人/启用时间。

待确认：停用库存口径与「即时库存查询」是否同一汇总接口（《仓库档案主PRD》§13 #2）。

[warehouse-form:1] 表单全局规则

warehouse-form

新增 / 编辑页全局

来源：《仓库档案_前端Demo版PRD》§4.2–§4.3、§六；《仓库档案主PRD》§7.1–§7.2

页面模式

  • 新增：标题「新增仓库」；保存后默认 ENABLED，主表单不展示启停用状态。
  • 编辑：标题「编辑仓库」；仓库类型 只读；仓库编码 未引用可改、已引用只读。
  • 主表单 不出现 启停用状态 与 停用原因（停用原因仅在停用弹窗）。

提交边界

  • 保存时全量校验；失败定位首个报错字段并阻断。
  • 编辑且已引用：不触发编码唯一性重复校验（《仓库档案主PRD》A11）。

结果处理

  • 成功：Toast「保存成功」，返回列表并可见最新数据。
  • 编码重复：字段红字「仓库编码已存在」。

离开处理

  • 取消 / 顶部取消：返回列表，不保存（Demo 未做未保存离开二次确认）。

[全局规则] 模块背景与链路

purchase-order-global

模块背景与链路

业务背景（§1）

采购订单是采购链路的起点控制单据：计划买什么、买多少、向谁买、什么价格；审核通过后作为执行与应付的原始凭据。审核前可编辑，审核后关键字段锁定，变更须驳回重提或走下游单据。

功能范围（§2 摘要）

In：手动创建/编辑、提交与审核、多次入库追踪、缺量关闭、待审核/待入库作废、草稿物理删除。

Out：采购计划自动补货、供应商协同、多级价格审批、合同价控、完整应付结算、批量导入。

单据定位与实体关系（§3）

项目内容
层级第 1 层——业务订单层（意图/计划）
下游采购入库单（审核通过后手动创建，1:N 分批到货）
flowchart LR
    A["主数据"] --> B["采购订单"]
    B --> C["采购入库单"]
    C --> D{"入库完毕?"}
    D -->|未入库=0| E["已完成"]
    D -->|人工关闭| E
    C --> F["库存+应付"]
关系说明
采购订单 : 采购入库单1:N
采购订单 : 供应商 / 仓库各 N:1
明细行 : 入库明细行1:N（分行多次入库）

[全局规则] 核心业务规则

purchase-order-global

核心业务规则（§7）

7.1 创建与提交

ID规则
R01保存草稿宽松：供应商/仓库/明细可空；已选商品行数量>0、单价≥0，否则阻断保存
R01b提交审核须供应商、入库仓库、≥1 有效明细，且满足 R02
R02每行：商品、数量>0、单价≥0
R03提交审核时同一商品编码不可重复；草稿保存不校验重复
R04下单日期默认当天，不可未来日期

7.2 审核与锁定

ID规则
R11审核通过后锁定：供应商、仓库、商品行、数量、单价、税率
R12审核后仍可改：采购备注、行备注、预计到货日期（待确认：本原型详情无编辑入口）
R13驳回回草稿，字段恢复可编辑

7.3 入库追踪

ID规则
R21仅待入库/部分入库可创建入库单
R22一张 PO 多张入库单（1:N）
R23入库确认累加「累计已入库」，更新未入库
R24路径①：未入库全归零→自动已完成
R25默认禁止超收

7.4 作废

ID规则
R31草稿物理删除，非已作废
R32待审核/待入库可作废
R33已有确认入库后不可作废 PO

7.5 关闭（缺量完结）

ID规则
R41路径②：部分入库可「关闭订单」→已完成
R42关闭不可撤销；未入库量保留可查
R43待入库无人工关闭，可作废
R44关闭时若有草稿入库单须提示并阻断确认

7.6 作废 vs 关闭

维度作废关闭（缺量完结）
适用待审核、待入库（无已确认入库）部分入库
结果状态已作废已完成
含义放弃未发生意图封存现状，余量不再收

7.7 价格（§7.7）

R51 默认采购价可带出可改；R53 审核后单价锁定须驳回改价；R55 数量差异与价格差异分开处理。

本页规则

本页职责：录入采购意图；仅 草稿 可进入编辑页（#/purchase/orders/{id}/edit）。

  • 路由：新增 #/purchase/orders/new；编辑 #/purchase/orders/{id}/edit（非草稿应重定向详情）。
  • 单号：保存后生成 PO{YYYYMMDD}-{序号}；新增页不展示单号。
  • 校验分层（V0.3）：
    • 保存（草稿）：V-PO-草稿保存宽松 — 允许供应商、入库仓库、明细均为空；若存在已选商品编码的行，数量须 >0 整数、单价 ≥0，失焦或点保存不合法则输入框下红字并阻断保存。
    • 保存并提交：V-REQ-PO提交* + V-BND-PO重复SKU + 全量行级校验；失败 V-PO-提交审核失败（首错定位 + Toast）。
  • 交互：修正输入后红字即时清除（V-UX-错误即时清除）；「保存」「保存并提交」点击后按钮 loading 至请求结束（V-UX-PO按钮loading）。
  • 状态变更：「保存并提交」成功 → PENDING_AUDIT → 跳转详情 Toast「已提交审核，等待审核确认」。

跨页规则：状态机、动作矩阵、R 规则全文 → 标注 「本页规则」 内 跨页规则 或 全屏阅读器。

待确认（原型/UI）：主 PRD R12（待入库/部分入库可改采购备注、行备注、预计到货）在本原型无详情轻量编辑入口，仅草稿走本编辑页。

[purchase-order-form:2] 商品明细

purchase-order-form

商品明细

来源：《采购订单字段清单》§二；《采购订单_Demo_新增编辑页》§五–§6.2；《全局字段校验与反馈规范》V0.3

  • 选择商品：多选弹窗，合计最多 50 行（V-BND-PO明细行数）；写入商品快照字段行内只读。
  • 草稿保存：允许 0 行；已选商品行数量/单价见 V-FMT-PO草稿行数量/单价（数量必须大于0、单价不能为负数）。
  • 保存并提交：
    • 至少 1 行有效商品（已写商品编码）；否则明细工具条上方区域红字：请至少添加一行有效商品。
    • 同一商品编码不可重复（V-BND-PO重复SKU）；区域红字：存在重复的商品编码，请合并或删除重复行。
    • 每行数量 >0 整数（上限 9,999,999）、单价 ≥0；行内/字段红字见 Demo §6.2。
  • 金额（含税） = 数量 × 单价，只读实时计算；税率枚举可空（字段清单）。

[本页规则] 本页规则

purchase-order-detail

本页规则

本页职责：只读展示全单信息；状态相关操作在页头（与列表行操作矩阵一致）。

  • 路由：#/purchase/orders/{id}（不含 /new、/edit）。
  • 完成路径：R24 未入库全归零 → 自动 COMPLETED；R41 部分入库「关闭订单」→ COMPLETED。
  • 作废 / 入库：R21～R33；已有确认入库后不可作废 PO（R33）。「创建入库单」跳转入库新增并预填 PO 号（入库模块原型待完善）。
  • 提交审核（草稿）：校验同表单 §6.2；按钮 loading（Demo §二）；失败 Toast 提交失败，{字段名}不满足条件。

跨页规则：状态流转表、动作矩阵、R 规则等 → 跨页规则 / 全屏阅读器。

待确认：R12 审核后改备注类字段 — 详情页无编辑入口，与字段清单 §五表述不一致，正式产品需补 UI。
